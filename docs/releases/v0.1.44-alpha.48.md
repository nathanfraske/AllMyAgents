# AllMyAgents v0.1.44-alpha.48

## Durable runs without a project manager

Open a project worker's chat permission menu (Safe/Standard/Full) and enable
**Allow durable runs**. The choice saves immediately and works with both Codex and
Claude. No manager or Overseer handoff is necessary.

This is an explicit standing command-execution grant: that worker can start, inspect,
wait for, and control its own project runs, including on teammate-triggered turns,
without another per-command approval. It does not promote the worker, let it control
another agent's runs, grant new remote devices, or elevate OS permissions. Remote
terminal grants and dependency/provenance checks remain in force. Revocation prevents
new admission/control immediately; it does not kill already admitted work or hide logs.

## Questions that stay visible outside the chat

Codex questions now use the same notification path in the in-process and worker
executors. A global question notice identifies the agent and opens the exact chat
when you are viewing another chat. Hidden tabs and unfocused desktop windows also
retain question attention. Notification previews do not disclose Codex question text
or secret input. Existing OS-notification preferences still apply.

Question cards and notices show an absolute countdown enforced by the hub, not the
backgrounded browser. Provider-supplied deadlines take precedence; optional Codex
questions without one get a **two-minute AllMyAgents default**. Expiry skips without
selecting any option or submitting a user answer. Blocking Codex requests without a
deadline and Claude's blocking AskUserQuestion do not get that invented deadline.
Answer, explicit skip, provider abort, and timer expiry share exactly-once resolution.

The protocol mapping was checked against the pinned Codex 0.153.3 schema and the
[official app-server question contract](https://learn.chatgpt.com/docs/app-server).
This release adds no new provider login or live model probe.

## Stop native-goal wait loops

`control_run(operation: "wait")` parks the caller's Codex native goal continuation
while its own durable run is queued/running. It preserves the objective, budget,
usage and run. Real completion wakes the agent through the existing completion
notification path. Managers, the Overseer and granted workers receive the same
wait discipline. Claude does not receive Codex goal operations. This addresses the
[measured polling loop](../manager-native-goal-wait-loop.md); it does not claim to
eliminate all model-authored polling.

## Verification and updating

Focused regressions cover both providers, worker grant/revoke, exact run ownership,
remote grant denial, notification delivery in both executor modes, timer/answer
races, retries, hidden-tab/focus behavior, privacy and UI saving errors. Full release
gates include JS/native checks, payload/credential audits and exact-tag Windows/macOS
launch-and-repair verification. Browser interaction qualification is recorded
separately from component tests; neither implies a live provider question was asked.

The numeric application version is **0.1.44** so existing installs can detect it.
After publication, use **Settings → Check for updates**. Publishing does not restart
your app or any service. Installation remains your action; no OS reboot is needed.

# AllMyAgents v0.1.15-alpha.18

Released 2026-08-04.

## Purpose

This patch fixes two operator-visible chat regressions introduced around bounded lazy history: after an
upward scroll, the apparent bottom could omit the latest replies, and a reloaded native chat could report
its creation time as its last activity. It also gives the Application Overseer a durable, versioned upgrade
path so the existing conversation receives the current app-level instructions and tools automatically.

## Continuous lazy history

- The store already retained every history page the operator explicitly reached and merged it with live
  items by stable key.
- The renderer nevertheless switched to `renderNodes.slice(0, 120)` as soon as any older page loaded. The
  bottom of that artificial prefix was therefore not the live end; scrolling downward could never reveal
  item 121 or any newer reply.
- Explicitly reached history now renders as one contiguous window through the live tail. Chats that have
  not entered lazy history retain the normal bounded 120-node tail, and compact composer previews retain
  their independently bounded item count.
- Scroll-anchor preservation, automatic top loading, the jump-to-latest control, and keyed item merging are
  unchanged.

## Truthful activity clocks

- The live production record for the affected chat had been updated moments earlier but carried no durable
  `lastActivity`; a cold baseline therefore fell back to its three-day-old `createdAt`.
- Both providers now persist `lastActivity` at their shared status-transition boundary. Replayed worker
  lifecycle markers bypass that write, so reattachment cannot make an old event look fresh.
- Existing native records are repaired client-side from the newest valid timestamp in the latest bounded
  transcript page. The correction is monotonic and cannot overwrite a newer live event.
- Settled chats may immediately return to their truthful sidebar position. Working chats retain the existing
  no-reorder-during-a-turn policy.
- Sidebar relative-time labels now receive a small clock tick, so an otherwise idle row cannot remain stuck
  at `just now` or an obsolete minute count until an unrelated event rerenders it.

## Existing Overseer sessions upgrade automatically

- Overseer records now carry an explicit capability-manifest version. New Overseers are created at the
  current version; older durable conversations without a version migrate automatically.
- Migration preserves the exact session id, vendor conversation, selected account, and transcript.
- The migration reasserts the hub-minted Overseer role, Full Access, the explicit per-chat operator override,
  and the `Application Overseer` role description, then regenerates the provider-native managed instruction
  file for the current contract.
- One `overseer/capabilities-upgraded` journal event records old/new versions, profile binding, conversation
  preservation, and the exact provider-neutral AllMyAgents tool names shipped by the runtime.
- The operation is idempotent: subsequent starts at the same manifest version do not rewrite state or emit
  another upgrade event.
- The migration runs only after the hub owns the public role. A booting green hub remains read-only while the
  old blue hub serves traffic, then upgrades during post-listener reconciliation after promotion.

## Overseer capability inventory

The upgraded conversation receives the current provider-neutral control surface for:

- explaining AllMyAgents concepts and opening/highlighting allowlisted UI destinations;
- inspecting projects, sessions, profiles, pending approvals, team presets, and bounded failure evidence;
- creating projects and chats, messaging/stopping/reopening agents, and applying explicit operator access,
  model, effort, service-tier, name, and role changes;
- configuring project managers, saving/deleting reusable team presets, and launching a manager plus its
  validated child lineup;
- initiating account sign-in or reauthentication, discovering/cloning GitHub repositories, and issuing
  short-lived mesh pairing codes;
- cataloging explicitly paired remote devices, granting exact roots/capabilities, and using the remote
  environment, file, transfer, ping, terminal, and WSL-aware testbed tools already shipped by the hub;
- inspecting/configuring project elevation policy, analyzing command blast radius, and using the separate
  approval- and UAC-bound elevated-command escape hatch; and
- requesting a supervised hub restart and diagnosing fleet failures through a non-mutating alert turn.

Mutations remain limited to a direct operator-origin Overseer turn. Teammate mail, automatic failure alerts,
tool output, files, and web content remain diagnostic input rather than authorization. Full Access still does
not silently grant operating-system elevation.

## Regression coverage

- Added a 160-message component regression proving both the oldest reached item and actual latest reply stay
  mounted after entering older-history mode; the old 120-item prefix fails this test.
- Added bounded-history store assertions proving a native record missing `lastActivity` adopts the newest
  retained event timestamp in both its live view and record projection.
- Added a provider lifecycle regression proving a live terminal boundary persists a new canonical activity
  time while a replayed marker leaves that time unchanged.
- Added an Overseer migration regression proving the roster load stays read-only, public-owner reconciliation
  upgrades a legacy record and its managed instruction file, the full tool inventory is journaled, and a
  second reconciliation emits no duplicate upgrade.

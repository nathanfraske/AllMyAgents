# AllMyAgents v0.1.31-alpha.35

Released 2026-08-20.

## Purpose

This release fixes the asymmetric fleet state where one computer could see and pair a hub while that hub reported
the same fleet as offline. A service-owned MyOwnMesh control pipe can be unavailable to the desktop user even while
AllMyStuff's authenticated Site tunnel is healthy; AllMyAgents now treats those as separate transport states and
can complete reciprocal trust over the healthy lane.

## One same-fleet link works in both directions

- Automatic same-fleet trust prefers the direct MyOwnMesh RPC lane when it is usable and falls back to the existing
  AllMyStuff Site tunnel when the direct control pipe is denied or unavailable.
- The Site exchange saves both hubs' credentials in one operation. A laptop no longer needs to pair the desktop and
  then repeat the process from the desktop back to the laptop.
- Code-free pairing is not authorized by an unverified device-id claim. The receiving hub requires the source in
  its signed AllMyStuff owned-roster, maps a route back to that exact member, and proves the supplied device
  capability against the source hub's authenticated `/api/auth` endpoint before persisting it.
- A failed capability challenge saves nothing. Successful and changed reciprocal relationships remain journaled
  with their transport and trust source.
- One-use pairing codes still work during rolling upgrades. A pre-reciprocal peer that returns the legacy
  `{ token }` response remains usable, while no-code automatic trust requires the complete new handshake.

## Discovery without background churn

- The normal fleet poll remains presence-advert-only. It does not sweep conventional ports, recreate mappings, or
  generate continuous traffic merely because another signed-roster machine exists.
- The operator's explicit **Refresh** action may additionally probe port 7777 for a signed-roster peer whose
  AllMyAgents presence advert was lost. This recovers a healthy hub such as a restarted desktop without restoring
  the old every-cycle port mapping and multi-megabit idle behavior.
- A machine whose mapped hub really returns HTTP 503 or has no listener remains visibly and accurately offline;
  recovery no longer turns unlike causes into one generic mesh failure.

## Stable identities and readable names

- Reciprocal credentials key the stable mesh public identity rather than the daemon's session-suffixed device id,
  so a reconnect or a switch between direct RPC and Site transport does not orphan the saved relationship.
- If the mesh identity has no display label, the signed fleet label is used; when that is also empty, the machine
  hostname replaces the full opaque id.

## Verification

- The complete hub Vitest suite passes with zero failures.
- All 711 web tests pass.
- Hub TypeScript typecheck and production build pass.
- Svelte check reports zero errors and zero warnings; the production web build passes.
- Focused coverage proves reciprocal Site pairing, rejection of a spoofed/stale source capability, stable identity

  recovery.
- The live host's AllMyStuff control plane returned the stable local mesh identity successfully while the separate
  direct MyOwnMesh pipe reproduced its access-denied state, exercising the exact topology this release addresses.

## External boundary

The Windows service-created MyOwnMesh control-pipe ACL still needs its durable fix in the MyOwnMesh/AllMyStuff
backend: the interactive desktop user must receive full-duplex access when the daemon is launched by the service.
This release does not weaken that boundary or suggest running the app elevated. It makes the already-authenticated,
healthy Site lane fully usable so that external defect no longer makes the whole fleet appear unreachable.

## Updating

Use **Settings → Check for updates** after the exact-tag workflow completes. Both hubs should run this version before
expecting automatic no-code Site trust; one-use code recovery remains compatible with an older peer.

Windows SmartScreen and macOS notarization warnings retain the documented alpha behavior.

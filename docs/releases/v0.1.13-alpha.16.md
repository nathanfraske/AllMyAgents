# AllMyAgents v0.1.13-alpha.16

Released 2026-08-03.

## Highlights

- The Application Overseer can now set up and reconfigure real projects and teams, save reusable team
  presets, teach the app by opening and spotlighting controls, and diagnose fleet failures without gaining
  authority from teammate messages.
- First run is reduced to the useful minimum: add one account, assign it to the Overseer, and let the
  Overseer guide or perform the rest. The longer visual tour remains optional and replayable.
- Claude worker sessions now carry durable `AskUserQuestion` requests over the authenticated worker
  channel instead of denying them or wedging their turn.
- Codex Full Access now uses the vendor's unrestricted host sandbox while retaining the hub's approval,
  audit, origin, and live-mode controls. Operating-system elevation remains an explicit separate boundary.
- Added an audited Windows UAC escape hatch, typo-resistant one-use pairing codes, rich research links,
  safe local-file reveal links, and a compact live Browser tab.

## Overseer setup and project orchestration

- The Overseer has a provider-neutral application guide covering accounts, models and effort, projects and
  scratchpads, chats and turns, project managers and children, worktrees, permissions, elevation, Browser,
  remote testbeds and WSL, pairing, journal/history, and recovery boundaries.
- Its first conversation offers two concrete paths: **set it up for me** or **show me around**. It answers
  only the relevant guide sections, then offers the next safe action instead of dumping a static manual.
- Direct operator turns can create projects and chats; send, stop, and reopen chats; change names, roles,
  models, effort, service tier, and permission mode; configure existing project managers; decide another
  chat's pending approval; initiate account sign-in or reauthentication; start GitHub imports; configure
  exact remote-device grants; issue pairing codes; and request a supervised hub restart.
- Durable team presets store a manager profile/model/effort/access ceiling, manager rules and instructions,
  fixed child types, child accounts/models/effort, worktree choices, tools, and delegated Git authority.
  The Overseer validates every child against the manager ceiling before launching the manager and visible
  direct-child chats into an existing project.
- Team launch messages are journaled as operator-origin instructions. A preset cannot manufacture authority
  by pretending a manager or teammate spoke for the operator.
- Existing manager records can be edited through the Overseer control plane in addition to the project-local
  **Edit project & managers** UI introduced in the prior cut.

## In-app teaching and UI highlighting

- The Overseer can query a closed catalog of real UI destinations, open the appropriate view or Settings
  tab, scroll the target into view, and draw a bounded dismissible spotlight with a short explanation.
- Supported destinations include Home, New Project, project overview, Overseer, Accounts, Chat defaults,
  Remote access, Safety, hub status, Managers, Browser, composer, permission controls, and older history.
- Highlight requests accept only allowlisted target identifiers and a 600-character message. They cannot
  supply selectors, HTML, script, coordinates, or arbitrary navigation.
- Only a direct operator-origin Overseer turn may request a highlight. Replayed journal events and remote
  fleet events never reopen a menu or resurrect an old spotlight.
- Missing or narrow-layout targets degrade to a centered, dismissible explanation instead of blocking the
  UI; Escape closes the guide.

## Failure diagnosis and provenance hardening

- A session entering an error state alerts the one hub-minted Overseer with bounded identifiers rather than
  copying arbitrary vendor error text into an authorizing prompt.
- The resulting diagnostic turn may inspect bounded recent journal evidence and produce a structured bug
  report with symptoms, evidence, likely cause, safe reproduction, and recommended owner. It cannot approve,
  change permissions, restart the hub, or mutate application state.
- The final audit closed a concurrent provenance edge: no teammate or system bus message is steered into a
  live operator-origin Overseer turn. Mail waits for the current turn to finish, then runs as a distinct
  diagnostic-only bus turn, so untrusted input cannot inherit application-wide authority.
- UI guide events carry escaped text through normal Svelte rendering; local and replay reducers accept only
  the same closed target set used by the hub.

## Permissions, manager scope, and elevation

- A direct project-manager assignment now includes a hub-verified, narrowly scoped authority statement.
  Children can recognize ordinary reversible work in their existing project/worktree as in scope without
  treating an ordinary teammate message as permission to widen tools, Git authority, access mode, or scope.
- Codex Full Access now selects `dangerFullAccess` for direct operator turns. Approval callbacks remain
  `on-request`, so the hub still enforces operator provenance, the ordinary-action allowlist, explicit ask
  rules, persistent per-chat grants, audit, and live Full-to-Safe tightening.
- Claude Full Access continues to route every ordinary tool through the hub's single approval authority.
  It removes repeated prompts after scope/provenance checks; Claude write tools remain worktree-contained,
  and interactive questions or user-authored ask rules remain human decisions.
- Full Access is not Windows administrator/root authority. Projects default to elevation disabled.
- The Overseer can configure a project-only or explicitly machine-wide elevation policy, analyze a proposed
  command for literal paths and high-impact patterns, and explain the declared blast radius. Execution then
  requires a separate non-auto-approvable operator decision and the operating system's own UAC consent.
- The Windows broker is one-shot rather than a resident privileged service. It uses direct argv process
  launches, bounded output, a 15-minute maximum, process-tree termination on timeout, and journals proposal,
  decision, start, completion/failure, hash, timing, and truncation facts.
- Literal-path analysis is deliberately described as advisory rather than an OS sandbox. Linux/macOS root
  brokering is not implemented in this cut; use an explicitly authorized testbed or run under the required
  account there.

## Claude worker question parity

- Worker-mode Claude turns now validate and correlate `AskUserQuestion` with stable session/tool/request
  identifiers, relay the durable request to the hub, and wait for the normal rendered answer lifecycle.
- Answer, cancel, interrupt, invalid-input, restart-unknown, and temporarily unavailable outcomes are mapped
  explicitly. An interrupt sends a correlated abort without racing registration.
- Long-lived question relays are exempt from the ordinary short RPC backstop but remain recoverable across
  authenticated worker reconnects. Other worker RPCs keep the existing bounded timeout.
- The worker never becomes a second approval authority: Full Access and **Always allow** decisions still
  relay to the hub so audit, mode changes, and origin clamps remain live.

## Pairing and remote controls

- New devices pair with an eight-character `XXXX-XXXX` code drawn from an ambiguity-free alphabet.
- A code is cryptographically random, stored only as a digest in memory, valid for ten minutes, accepted
  once, and discarded after ten failed guesses. The long-lived device token is returned only after a valid
  exchange and is never written into the journal.
- Existing permanent tokens remain compatible and available under an Advanced recovery disclosure.
- Pairing remains connection identity, not execution authority. Remote read, write, terminal, and WSL
  access still require exact target-root and per-chat capability grants from the prior release.
- The Overseer can issue a short code and configure those existing exact grants during project setup.

## Browser and transcript links

- The live Browser side-panel control is now a small icon-only tab at rest. Hover, keyboard focus, or an
  open panel expands it to the accessible **Browser on/off** label.
- HTTPS research links receive locally rendered GitHub, PDF, or generic website identity badges. Rendering
  a transcript performs no favicon or metadata request.
- Absolute Windows, UNC, `file:///`, and POSIX transcript links are sanitized into inert reveal controls.
  A desktop click asks a bounded native command to canonicalize an existing absolute path and reveal it in
  Explorer/Finder/the file manager without executing the target or invoking a shell.
- A plain-browser or remote UI cannot reveal a file on its host; it copies the path to the local clipboard
  and reports that outcome. Forged local-path data attributes in raw model HTML are removed before parsing.

## First-run experience

- Fresh installs now open Accounts, wait for one successful sign-in, move directly to the Overseer setup
  in Settings, and finish once that account owns the Overseer chat.
- The detailed application tour is optional and independently replayable. Existing installations with real
  accounts/chats do not get forced back through first run.
- Tutorial completion, skip, and replay state remain durable, and the setup UI stays open between the
  account and Overseer steps instead of making the user rediscover Settings.

## Safety, compatibility, and known validation limits

- Existing journals, profiles, projects, sessions, permanent mesh credentials, manager records, and remote
  grants remain compatible. Team and elevation tables are additive and created automatically.
- No UI teaching operation can click a control, enter data, or approve an action on the operator's behalf;
  it can only navigate to and visually explain an allowlisted destination.
- No transcript render performs network or filesystem I/O. Local reveal requires an operator click and
  validates again in native code.
- The extra Rust unit-test binary compiled but could not start on this Windows host due to
  `STATUS_ENTRYPOINT_NOT_FOUND` before the test harness ran. This is not a failed assertion; the required
  native check/Clippy gates and the optimized release executable all compiled successfully.
- A clean-profile installed-app smoke was not launched locally because the operator's active AllMyAgents
  instance owns port 7777 and its live hub must not be displaced. The tag workflow must still complete the
  clean Windows/macOS build and artifact checks.
- The production web bundle currently emits a non-blocking 808 KB main-chunk advisory; code splitting is a
  future performance improvement.
- Windows installers remain without Authenticode signing, and macOS remains unnotarized and unproven on
  physical hardware. This remains alpha software operating on real local credentials and project files.

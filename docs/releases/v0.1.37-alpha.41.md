# AllMyAgents v0.1.37-alpha.41

Released 2026-08-30.

## Purpose

This release gives managers and the application Overseer a durable way to wait for GitHub CI without holding an
agent turn or a polling shell. It also closes the remaining live-edge scrolling, cold-history, and journal cleanup
gaps reported after the previous alpha.

## Durable GitHub CI completion wakes

- The new `monitor_ci` tool watches either an exact pull request number or an exact GitHub Actions workflow run id.
  Agents can create, list, and cancel their own persisted watches.
- A terminal success or failure posts one action-required bus receipt and wakes the owning idle manager or
  Overseer. The wake remains bus-originated and permission-clamped; monitoring does not grant mutation authority.
- Watch creation requires the operator-owned `workflow_runs` automation capability for the exact session/project
  and repository. Project sessions are confined to their verified safe Git remote, and the projectless path is
  limited to the hub-minted application Overseer with an exact session grant.
- Pull-request success is conservative: all observed check runs and commit statuses must be successful, and the
  complete check set plus head SHA must be identical on two polls. Terminal failures wake immediately.
- GitHub/API errors use bounded exponential backoff and are journaled as monitor degradation, never reported as a
  CI failure. Fixed `gh api` argument vectors reuse local GitHub authentication without reading or storing tokens.
- Watches survive hub restart and blue/green ownership changes. Notification receipts are idempotent, duplicate
  targets share one query cycle, and active/retained watch counts are bounded.
- Manager and Overseer methodology now explicitly says to arm this monitor after dispatching Actions work instead
  of holding a shell open, repeatedly polling, or depending on a human to notice the run.

## Transcript and history recovery

- Live-edge following is based on the real bottom distance. Streaming messages keep moving a transcript that is
  already at the bottom, while wheel, touch, or ordinary upward scrolling detaches only for deliberate scrollback.
- Jump to latest performs a real bottom correction, and returning to a chat that was left at its live edge restores
  the live edge after the pane and retained history settle.
- Cold active conversations may fetch one additional bounded history page when tool and lifecycle events leave the
  initial page with fewer than six actual user/assistant messages. This improves context without restoring an
  unbounded whole-session load.
- History reads retry once against the server's current generation after maintenance rotates the checkpoint.
  Failure remains visible with a Retry action rather than being rendered as an empty conversation.

## Journal maintenance and Overseer account handoff

- Condensation now limits its candidate frontier to the newest verified recovery generation and re-evaluates the
  covered prefix. It can reclaim safe older rows while newer superseded rows wait for the next snapshot.
- Size budgets, projection budgets, snapshot waits, and transient writer contention are reported as intentional
  deferred maintenance rather than an unavailable or unobservable journal state.
- Terminal maintenance results always clear their progress guard, preventing a completed/deferred child from being
  misreported later as observation loss.
- The application Overseer account picker calls the singleton Overseer reconfiguration path. A successor Overseer
  takes over on the chosen local account instead of spawning a normal Unfiled chat.

## MyOwnMesh-native testbed boundary

- Product documentation now identifies the exact fail-closed seam for a MyOwnMesh-native peer without AllMyStuff:
  typed control degradation, signed peer identity, authenticated bootstrap, capability/architecture attestation,
  least-authority privilege selection, provenance, and `outcome_unknown` handling.
- mDNS/LAN presence remains locator-only and never authorizes deployment. The documented qualification sequence
  requires no OS reboot and separates any future bounded service restart.
- This is a durable cross-repository contract and documentation slice only. It does not claim that the upstream
  authenticated transfer/terminal contract or live K3 deployment path has shipped in this version.

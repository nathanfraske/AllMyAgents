# AllMyAgents v0.1.21-alpha.24

Released 2026-08-07.

## Purpose

This release makes long-running managed teams recoverable without deleting their evidence, prevents background
coordination from repeatedly resuming already enormous provider contexts, adds explicit resource modes for the
Application Overseer, and turns notification, journal-storage, and mesh-route state into bounded operator-facing
facts.

It also closes a live journal-maintenance false failure observed while preparing this cut. The installed hub had
completed ten consecutive cleanup runs, then one maintenance child lost a SQLite writer race and reported
`database is locked`; the next scheduled run completed and deleted 2,519 rows / 1,968,397 payload bytes. The
release gives the isolated maintenance connection a longer bounded wait and classifies remaining writer
contention as a deferred retry while preserving real failures for I/O, integrity, schema, and logic errors.

## Context pressure and provider compaction

- Every Claude SDK query—including a resumed conversation—enables the provider's supported automatic compaction
  window at 500,000 tokens. The application does not claim a manual compaction occurred when the driver exposes no
  on-demand trigger.
- Modern Codex app-server token-usage events are normalized into provider-neutral context-used/context-window
  telemetry and persisted without retaining the raw vendor envelope.
- When an idle recipient is at or above 500,000 context tokens or 80% of its known context window, manager/bus
  mail is durably queued without launching another expensive resumed turn. An already-running recipient still
  receives a normal steer, and queued mail is folded into its next accepted operator-started turn.
- `wake=false` is a first-class durable bus intent for checkpoints and FYIs. Deferral is returned as queued—not
  failed—so a manager can distinguish preserved mail from a rejected assignment.
- Managers can optionally stop dispatch to an account at an authoritative 100% usage limit. Paid overage or
  usage credits explicitly bypass that guard; legacy managers retain their prior behavior until the operator
  enables it.
- Claude SDK token-priced spend is labelled only as an API-equivalent estimate for the current hub run. It is no
  longer presented as subscription-plan utilization; the provider's session/weekly quota bars remain authoritative.

## Recoverable manager and worker lifecycles

- Managers gain the provider-neutral `manage_child` operation. `retire` accepts only an idle, errored, or stopped
  direct child, releases its live-child capacity slot, and preserves its identity, transcript, tasks, branch,
  dirty files, and worktree. `reactivate` restores it only when its team is active and live capacity permits.
- A running/starting child cannot be retired mid-turn, nested descendants cannot be mistaken for direct children,
  and activating a stashed team cannot silently reopen a deliberately retired child.
- Manager roster/status output and the sidebar show retired children separately, including the operator/manager
  reason, while keeping the preserved chat visible.
- After a compaction failure or unavailable same-chat boundary, a manager now has an actionable fallback: retire
  the old child, create a fresh successor with `spawn_agent`, and retain the old record for audit or later reactivation.
- When explicitly enabled by the operator's manager grant, a direct worker can create bounded same-account,
  same-model one-shot descendants. They inherit the worker's exact authority ceiling, appear beneath that worker
  as `Name II`, `Name III`, and so on, remain inside the root manager's inspection/approval hierarchy, and cannot
  create another generation.
- Managers and Overseers receive bounded, durable evidence of direct operator steering and permission decisions,
  so they can distinguish an operator intervention from an agent acting outside its assignment.
- A child approval outside the direct manager's exact tool/Git ceiling escalates to the available Overseer instead
  of wedging at an authority that cannot decide it. The Overseer still cannot manufacture operator provenance.

## Overseer resource modes

- Settings adds Standard, Tokenmaxxing, and Eco modes. Only a direct operator turn may change the durable policy;
  teammate, manager, remote-peer, and system-origin turns cannot activate resource policy.
- Tokenmaxxing directs the Overseer to inspect live account usage/reset data and ask what useful review, audit, or
  verification outcome should consume capacity that will reset soon. Saved ideas are suggestions, never permission
  to invent work, and the configured concurrency bound remains subordinate to account/team/hub limits.
- Eco directs the Overseer toward the cheapest still-capable model, lower effort, existing idle agents, minimal
  evidence-producing test slices, and explicit operator confirmation before materially exceeding the saved policy.
- Each mode retains its own bounded guidance and idea pool when another mode is selected. Capability contract v6
  is regenerated for existing Overseer sessions so both Claude and Codex receive the active mode after restart,
  resume, or compaction rather than relying on remembered prose.

## Notifications and privileged-operation truth

- A durable in-app notification center stores at most 1,000 delivery records for at most 30 days. The underlying
  lifecycle/approval evidence remains in the main journal; the inbox is a bounded replaceable delivery projection
  and does not amplify the journal with duplicate notification events.
- Manager and Overseer completions notify by default; routine worker completions stay with their manager unless
  the operator opts in. Errors, permission/elevated approvals, stalls, and journal/recovery pressure are enabled by
  default. Stable dedupe keys prevent replay/restart duplicates.
- Desktop notifications are independently opt-in and request renderer/OS permission only after an explicit click.
  Enabling them never retroactively emits old in-app rows.
- Settings reports the privileged-operation broker honestly. No permanently elevated resident service is added:
  Full Access remains separate from Administrator/root, and elevated execution still requires a bounded project
  policy, blast-radius analysis, a distinct operator approval, and a one-shot OS elevation boundary.

## Journal growth, recovery retention, and maintenance

- `pnpm journal:audit [path-to-hub.db]` reports file/WAL size, reusable SQLite pages, allocated pages, event-kind
  payload leaders, recent daily growth, largest sessions/payloads, maintenance frontiers, and backup/recovery
  logical versus unique bytes. `--fast`, `--json`, and `--check` support bounded automation and integrity review.
- A low-frequency storage monitor reads file metadata and SQLite page counters without grouping/scanning the event
  table. It warns at bounded allocated and retained-copy thresholds with one day-scoped notification instead of
  continuously appending pressure events.
- Condensation now removes an old `item/started` row only after the exact completed item is durable. Existing
  journals rewind only the bounded transient projection needed to classify those rows.
- Recovery generations are retained by an explicit byte budget as well as count, while always keeping the newest
  verified generation. Backup sidecars remain covered by rotation and retained-byte accounting.
- The maintenance child uses a 30-second busy timeout while the interactive hub retains its shorter latency bound.
  Residual `SQLITE_BUSY`/`SQLITE_LOCKED` contention terminates as a truthful deferred retry with resumable
  projection/delete frontiers; corruption, disk-full, I/O, schema, and invariant failures remain terminal.

## Mesh route discovery

- The direct MyOwnMesh bridge discovers all eligible non-helper AllMyStuff networks instead of pinning the app to
  one globally scored mesh. Duplicate peer presence is merged by active status and latency.
- Outbound RPC selects the network on which that exact peer is active, refreshes discovery before declaring it
  unavailable, and returns a specific pending/offline/no-route explanation.
- Inbound Hub RPC is registered on every eligible shared network with independently managed sockets and reconnects.
- Presence-advertised AllMyAgents Hub sites on owned devices are automatically mapped (bounded to 64 routes and
  health-checked) so opening the Remote tab is no longer required to create the underlying route.

## Durable transcript attachments

- Rendered images/files now retain a usable attachment URL across reload. Because ordinary image/download elements
  cannot attach the API bearer header, the URL may carry the device capability only for one exact read-only
  `GET /api/sessions/:session/attachments/:attachment` route.
- Query authentication is rejected for session lists, every other API, wrong tokens, and all mutation methods.
  Attachment identity, session ownership, quotas, and content headers continue to be enforced by the hub.

## Known boundary

Neither current provider driver exposes a reliable application-owned on-demand compaction call. Claude performs
automatic compaction at a provider turn boundary and Codex reports its native compaction lifecycle; the app does
not pretend otherwise. Managers now have the reversible retire-and-successor path when that boundary cannot be
created in the same chat.

## Updating

Existing installs can use **Settings → Check for updates** after the signed release assets are published. The
GitHub release also provides Windows MSI/NSIS and Apple Silicon/Intel macOS downloads. Windows SmartScreen and
macOS notarization warnings may still appear during the alpha; updater signatures and release checksums remain the
integrity boundary for this cut.

# AllMyAgents v0.1.10-alpha.13

Released 2026-07-31.

## Highlights

- Made account sign-in completion bounded and cancellable instead of allowing the final profile rescan to
  wedge the renderer indefinitely after credentials were already durable.
- Hardened verified journal backup and recovery behavior, including failure-path rotation, byte budgets,
  free-space admission, full integrity verification, debris cleanup, and an explicit operator acceptance
  path for a known-good legacy journal.
- Reworked long chat history into bounded hub pages that load automatically near the top and accumulate
  without evicting content already visible in the pane.
- Added project-local editing for project and manager configuration, plus explicit bounded permission
  overrides and immediately rematerialized child authority instructions.
- Added safe account display names and an in-flow Browser side panel coordinated with the Agents panel.
- Added native WebView2 renderer-failure diagnostics and recovery for the otherwise silent frozen-window
  failure class.

## Account and authentication fixes

- Wrapped the post-login profile rescan in the same eight-second request deadline and abort signal as the
  rest of the login flow. A rescan failure no longer turns a successfully persisted credential into a
  permanent "Preparing sign-in safely" modal.
- Added a whole-attempt deadline covering capture, waiting, settling, and completion.
- Made Cancel and Escape effective during every login phase, including completion and settling, and kept
  cancellation tied to the exact attempt instead of a profile-wide guess.
- Treats a failed final rescan as non-fatal after credential durability is established, then reconciles the
  account list from the live profile stream.
- Added an explicit re-authenticate action for every account before it reaches a failed state.
- Added persistent account display-name aliases. Credentials, sessions, usage, grants, instructions, and
  profile directories continue to use immutable IDs; selectors show both alias and ID where identity
  matters, and duplicate aliases are rejected.
- Hub startup diagnostics now print the resolved profile and data roots, making split-root account failures
  diagnosable from the log.

## Journal backup and recovery fixes

- Backup rotation now runs before snapshotting and in a `finally` path, so enrollment, backup,
  verification, publication, or recovery-generation failures cannot skip retention indefinitely.
- Replaced generation-count-only retention with oldest-first count and total-byte budgets while always
  retaining the newest verified snapshot.
- Added free-space admission based on the source database size plus a reserved safety margin. Insufficient
  capacity is reported before starting a large online backup.
- Backup verification now uses full `integrity_check`, verifies the events table, and rejects a schema-only
  snapshot when the source already contained events.
- Keeps compatibility snapshots and strong identity-bound recovery generations within bounded evidence
  budgets, reporting degraded state when strong publication fails instead of calling the backup restorable.
- Ensured backup generations cannot overlap, survive supervisor handoff correctly, and settle or time out
  cleanly during restart and shutdown.
- Recovery directories now use realpath-based containment checks, accepting valid descendant paths across
  Windows redirections without requiring their resolved parent strings to be identical.
- Failed recovery preparation removes its unpublished classifier and restore copies. Durable plans retain
  their owned artifacts and remain resumable.
- Added a journal-offline operator command to inspect and accept an explicitly known-good `hub.db` by exact
  SHA-256 plus a recorded reason. It runs full integrity and payload checks, archives prior recovery
  metadata as evidence, creates a new bound identity, and journals the acceptance decision atomically.
- Made that evidence archive restart-complete: each move and directory boundary is made durable, and a
  resumed acceptance rebuilds its manifest from the archive itself instead of forgetting files moved by
  the process that crashed.
- Re-gated condensation under its bounded worker budget: projection indexes commit in 5,000-row batches,
  cleanup commits in bounded transactions, and an unfinished run pauses before the supervisor deadline and
  resumes on the next interval instead of repeatedly discarding one giant transaction.

## Chat history and interaction fixes

- Opening a native chat now hydrates its latest transcript through the same bounded journal-history API
  used for older pages instead of depending on a massive cold WebSocket replay.
- Scrolling near the top automatically loads the next older page; the button remains as a visible and
  retryable fallback, with transport and decode failures shown in the chat.
- When the latest page is too short to produce a scrollbar, history pages continue filling automatically
  until the pane becomes scrollable or the authoritative beginning is reached.
- Loaded pages now accumulate only as requested and are never silently replaced. Continued live output,
  replay completion, scrolling, and tabbing away and back no longer delete the visible transcript prefix.
- Preserves the scroll anchor when older content is inserted and offers a direct jump back to the live end.
- Restricted pane reordering drag behavior to the labelled chat header. Transcript and composer text can
  once again be selected and copied without dragging the native window or pane.
- Pressing Enter while a turn is still starting now queues and clears the message. It no longer attempts a
  premature steer or leaves duplicate text in the composer.
- Fixed Claude's transient `Tool permission request failed: AbortError: Stream closed` cascade after a
  mid-turn steer. Claude emits one result per submitted streaming message; the adapter now keeps stdin and
  its shared permission channel open until every accepted prompt/steer has produced its corresponding
  result. A deterministic two-result regression covers the exact live failure ordering.
- Updated the bundled Claude Agent SDK and Claude Code runtime to 0.3.220/2.1.220 for the current upstream
  reliability baseline.
- Reconciles each session against the hub's authoritative roster after reconnect, with a sequence fence so
  a delayed HTTP response cannot overwrite a newer streamed status. Active work therefore no longer sits
  incorrectly at Ready after renderer or socket gaps.

## Projects and managers

- Creating an agent from a project's plus control opens the newly created agent chat immediately.
- Opening a manager from the sidebar or project summary now enters the full project-scoped manager
  conversation and hydrates it through the normal chat-history path.
- Added **Edit project & manager** to Project Overview. Projects can be renamed without changing their
  filesystem identity, and existing manager account/model/effort, rules, live-child limit, child permission
  ceiling, tools, Git authority, worker types, and launch brief can be edited in context.
- Manager permission controls now explain the operator-granted boundary. Crossing it is an authenticated,
  explicit one-chat operator override rather than a silent no-op or a rewrite of the manager's reusable
  bounds.
- Managers can adjust an existing direct child's permission mode inside their live operator-granted child
  ceiling, including a per-child ceiling explicitly extended by the operator; sibling grants are unchanged.
- Changing child Git/tool authority or permission mode now rematerializes that child's native
  `AGENTS.md`/`CLAUDE.md` instructions immediately, so a success response cannot leave stale effective
  instructions on the next turn.

## Browser, renderer, and Codex reliability

- Browser controls now live in a chat-side popout matching the Agents panel. The two panels are mutually
  exclusive, remember their per-chat state, and retain the native **Show browser window** action.
- Added a native WebView2 `ProcessFailed` handler. Renderer exit, unresponsiveness, and frame-renderer exit
  are written to the desktop diagnostic log and trigger a host-side reload even when JavaScript is no
  longer running.
- WebView2 failure-handler registration is asynchronous and non-blocking; desktop startup no longer waits
  on work that must itself execute on the UI thread.
- Repairs Codex rollout indexes whose absolute path still points into a vanished Microsoft Store/MSIX
  AppData virtualization root. Only an existing, same-thread rollout beneath the current profile's real
  `sessions` directory is eligible; traversal, missing files, and ambiguous paths are left untouched.

## Status and layout polish

- Replaced the full-width journal-maintenance bar with a compact indicator beside Hub connection. Both
  indicators open accessible detail popouts and close on Escape or outside interaction.
- Journal status reports phase, verified progress counters, bytes reclaimed, detail, and idle/unobservable
  states without occupying the application banner lane.
- Supervisor restart logs now report the configured public port instead of hard-coding the production
  port, so isolated and alternate-port diagnostics describe the transition accurately.
- Account aliases are used consistently in sidebar, usage, account pickers, project creation, manager
  setup, project settings, and chat headers while immutable IDs remain visible in authority-sensitive
  selectors.

## Safety and compatibility

- No account, project, session, credential-directory, or journal identity is renamed in place.
- No lossy journal-history retention policy is enabled; older transcript content remains authoritative in
  SQLite and is fetched lazily.
- Known-good journal acceptance is never automatic and requires the hub to be offline, an exclusive
  recovery lease, the exact inspected digest, and an operator reason.
- This remains alpha software. Windows installers are not Authenticode-signed, and macOS bundles are not
  notarized.

# AllMyAgents v0.1.18-alpha.21

Released 2026-08-05.

## Purpose

This release closes the journal failure chain that could turn slow maintenance into a supervisor kill and then
turn a recoverable publish/activate interruption into a permanently offline hub. It also repairs the remaining
account-login renderer freeze, lazy transcript paging across recovery generations, packaged project deletion,
Codex browser re-authentication, and fleet-wide Overseer inspection.

The preceding manager-team, provenance, large-journal, and Codex authentication work remains fully logged in
`docs/releases/v0.1.17-alpha.20.md`; this ledger records only the additional release delta.

## Crash-atomic journal lineage and self-repair

- A newly verified recovery generation is published and activated through atomic, fsynced metadata replacement.
  A process death can leave generation N active or N+1 ready to adopt, but not an ambiguous half-written binding.
- Boot reconciliation verifies and adopts a complete published-but-unactivated generation. An incomplete or
  unverifiable candidate is discarded, while authoritative rollback receipts remain mandatory and cannot be
  bypassed by a superficially valid snapshot.
- Interrupted classifier staging is removed only after exclusive recovery ownership is acquired and only for
  canonical staging names owned by the recovery subsystem. Unrelated directories are never swept.
- `head.json` is treated as rebuildable derived metadata. Missing or stale head state is reconstructed from the
  verified root binding and snapshot instead of creating a permanent boot refusal.
- Normal shared preflight detects authoritative repair work but does not mutate it. The supervisor retires shared
  journal owners, obtains the exclusive lease, performs reconciliation, and then starts the hub.
- Crash-injection coverage force-kills child processes immediately after generation publication and after
  classifier fsync. The next boot proves adoption or safe cleanup and reaches a ready journal without hand edits.

## Progress-aware maintenance and supervision

- Backup, snapshot, verification, publication, and condensation emit an instance-bound out-of-band heartbeat with
  phase, rows committed, bytes written, active state, and whether the current lineage step is non-interruptible.
- Heartbeats contain a random owner identity in addition to the PID, rejecting stale files after PID reuse. A
  heartbeat write failure is diagnostic and cannot itself fail a valid backup.
- Work and no-progress windows scale with the measured journal instead of applying a fixed 4m50 kill to every
  database. Condensation reports progress at durable batch boundaries rather than only at the final commit.
- The supervisor starts the no-progress clock at the first failed health request, resets it whenever durable work
  advances, and suppresses termination during protected verification/publication phases. One slow `/api/health`
  response is no longer interpreted as a dead process.
- Every supervisor termination decision is tied to the exact child instance and requires a full no-progress
  interval. Slow but advancing maintenance is allowed to finish; a genuinely wedged child remains recoverable.

## Account sign-in correctness and responsiveness

- The tutorial login mirror no longer reads reactive `login` state from the same Svelte effect that writes it.
  The prior value is read through `untrack`, and an equivalent next view preserves object identity instead of
  scheduling another effect pass.
- This fixes the observed failure where OAuth completed, the hub recorded `signed_in`, and the renderer then
  consumed CPU forever on “Preparing … sign-in safely”. The hub and vendor login flow were not the source of that
  freeze.
- Three controller regressions prove identity stability, convergence under 25 repeated mirrors, and propagation
  of genuine state changes. A rendered Settings-modal regression runs the actual callback/effect path and proves
  that `settling` maps to tutorial `waiting` and converges across subsequent render ticks.
- Codex browser OAuth URLs captured from the piped CLI are always handed to the app-owned native opener in the
  desktop build. A piped CLI is no longer assumed to have opened its own browser.
- One-click Codex re-authentication explicitly resets to browser OAuth even if the add-account form previously
  selected device mode. Device authentication remains an intentional remote/headless option.
- Every app-managed Codex home pins `cli_auth_credentials_store = "file"` while preserving unrelated user config,
  keeping its credential in the profile-owned `auth.json` and avoiding ambient keychain/cache drift.

## Transcript, project, Overseer, and workspace repairs

- Journal-history API conflicts now carry both expected and actual generation identities. Initial and older-page
  loads retry the same stable sequence cursor once against the authoritative generation.
- A generation retry does not clear already reached items, discard the live tail, or replace the user's scroll
  anchor. “Load older history” and scroll-to-load can continue after maintenance changes the snapshot generation.
- Packaged browser CORS now advertises `DELETE` alongside `GET`, `POST`, and `OPTIONS`. The project deletion dialog
  reaches its authenticated hub route instead of surfacing the browser's opaque “Failed to fetch”.
- Tests cover both safe project removal (records detached, disk preserved) and explicitly confirmed project/file
  removal (records and exact disposable directory removed).
- Existing Application Overseer sessions migrate in place to capability contract v3. Their injected contract
  makes `overseer_control` the primary app mutation surface and directs fleet inspection to AllMyAgents
  `list_agents`/`peek_agent`, not a vendor-native project-scoped tool with the same short name.
- The worktree collision detector checks path existence before invoking Git, logs a missing checkout once, and
  retains the last trustworthy stashed-team attribution rather than spawning and logging the same failed process
  every few seconds.

## Verification

- Journal recovery coverage includes complete and incomplete generations, immutable rollback receipts, exact
  ownership boundaries, real process kills at both crash points, and independent recovery after each interruption.
- Hub and web typechecks, Svelte diagnostics, full unit/integration suites, production builds, Rust `check` and
  warning-free `clippy`, credential-firewall self-tests, and the packaged hub-runtime audit pass on the candidate.
- A fresh isolated Windows sandbox starts with an empty journal, publishes and enrolls its backup lineage, then
  completes a blue/green restart with the replacement process serving the same public port. The sandbox uses an
  isolated profile directory and is deleted after the proof.
- The release workflow records the final Windows installer build and updater artifacts against the exact merged
  commit and tag.

# AllMyAgents v0.1.49-alpha.53

## Daybreak and account model discovery

- Daybreak is a separate per-chat switch in the model picker, with account-advertised model choices and Default / Recommended where available. Blue/Red selection appears only when the account advertises both programs.
- The model and Daybreak program travel independently through the hub and worker. Off explicitly requests standard mode; changes during a turn apply to subsequent turns. Unsupported combinations are rejected, and provider denials never silently switch the model or disable Daybreak.
- The bundled Codex client advances to 0.156.1, including the newer account catalog protocol used for GPT-6 Sol/Luna and their advertised Daybreak availability. Refresh the account's model list after updating; catalog entries are not a substitute for provider entitlement. Saved helper model selections are not automatically migrated.
- Confirmed terminal credit/usage exhaustion remains visible to the operator but no longer wakes the Overseer simply because the affected account differs. Authentication, policy, context and unknown errors are not silently classified as exhausted credits. Approval assistants remain approval reviewers, not a new general-purpose error-triage model.

## Operator-owned individual approval delegation

- The existing Overseer can be explicitly configured to review GitHub branch creation, job reruns and workflow file creation/replacement using exact requester/project/repository and category, branch/path/head/job, risk/effect and expiry bounds.
- Review includes the complete bounded payload, before/after source, structural diff, hashes and execution/effect evidence. Paged inspection must finish before a fresh one-shot token is issued; decisions recheck source, policy and grants and retain an audit reason. Expired, revoked, resolved or changed requests fail closed. A timeout is not labeled an operator rejection.
- **An update does not activate or broaden delegation.** Existing Arnold-only policy remains as configured. Additional review repositories require a separate explicit resource grant; approval authority cannot override tool/device, origin, platform, provider or OS boundaries. Arbitrary executable workflow changes remain high risk and require explicit effect delegation plus a reviewer able and permitted to assess them.
- **Not blanket GitHub approval:** `create_tree`, `create_commit` and `update_ref` remain unsupported by the review adapters. Missing evidence and unknown operation semantics still require operator attention. A job rerun may include dependent jobs, and one-shot local approval does not promise an atomic external transaction or exactly-once remote execution. No historic request is replayed.

## Managers respect direct operator work

- Managers can inspect hub-verified active/queued operator direction and a timestamped contact receipt for a child, without copying private operator message text into its roster.
- While direct operator work is active or queued, manager shelving, replacement and new live assignments cannot silently stop it. Manager mail queues for the next turn instead of interrupting that work. The operator's own stop controls and all existing permissions remain intact; a child's unsupported claim of authorization is not trusted evidence.
- Hub shutdown cancels manager watchdog/pulse timers before asynchronous teardown and prevents late callbacks from re-arming them against a closed journal.

## Task-first work, tool help and usage warnings

- Lean coordination now defaults on for both new and existing chats. The durable `task_plan` ledger records bounded outcomes, completion criteria and dedicated owners. App work requires an active assignment; compaction, native checklists and routine mail cannot create new outcomes or reopen finished tasks. Fresh operator input is required to add scope.
- Finishing requires completion evidence and no outstanding queued/running/uncertain durable runs. Completed objectives hold further app work and routine mail wakes. Native Codex goal continuations are paused; an unconfirmed pause warns the operator rather than claiming a confirmed stop. This is not a universal native-tool sandbox or automatic proof that each command is relevant.
- App tool failures permit one safely repeatable read retry before an operator-help hold. Ambiguous writes, authentication and exhausted credits do not acquire retry permission. External/native tools can report through `report_tool_failure`. No helper model or automatic infrastructure-repair loop is launched.
- Default-on warnings notify the operator at 100,000 reported non-cached tokens per turn or 80% measured context occupancy. Thresholds and controls are configurable; missing counters and dollar costs are not guessed. Ordinary coordination stays quiet, and task completion history survives native plan replacement.
- Existing agents/managers/Overseer receive current controls without recreation, at the next host turn/resume after updating. Prior manager assignments are adopted without scope rewrites or artificial wakes. See [coverage and research](https://github.com/nathanfraske/AllMyAgents/blob/v0.1.49-alpha.53/docs/agent-efficiency-controls.md) for native-provider limits and the distinction between structural enforcement and guidance.

## Faster qualification and quieter run notifications

- Linux installed-node qualification removes the forced 125-second wall-clock wait while retaining project-owned package extraction, checksum, configure, installed-executor, duplicate-start and timeout checks. A short real child and deterministic long-deadline regression replace the soak; normal CI and the legacy `--short` entry point run the complete checks.
- Production compilation no longer emits discarded test JavaScript; the full test/typecheck gates still cover those sources. Manager tests reuse an immutable Git seed through independent copies, and maintenance-child tests resolve their loader independently of the invoking directory and report early failures accurately.
- Durable completion messages use bounded command/error previews and point to retained exact records and cursor-paged logs. Successful stderr is no longer presented as a failure. Audit, cancellation, unknown-outcome/no-replay safeguards and full evidence are unchanged.
- Local performance qualification passed 1,786 hub tests (one existing skip) at both four and eight workers. Two local compile comparisons reduced wall time by 34–38% with identical production output. These are local measurements, not a fleet-wide speed guarantee; the four-worker default and all existing CI checks remain intact. No paid summarizer was added.
- Normal trusted CI targets exclusive v2 Windows/Linux/Intel Mac labels bound to the run, attempt and literal job key, with persistent build caches. Intel Mac checks are additive; Apple Silicon stays hosted because its local pool is not configured. Fork PRs stay hosted, and an explicit hosted diagnostic mode still runs the full checks. Windows, Intel Mac and Linux amd64 release builds use the same v2 contract; existing installer/launch/repair verification remains required and hosted pending local installed-app qualification. Linux arm64 and release coordination also remain hosted. Publication remains contingent on fleet readiness and green exact-head/tag gates. See [the exact runner contract](https://github.com/nathanfraske/AllMyAgents/blob/v0.1.49-alpha.53/docs/fleet-ci-routing.md).

## Updating and remaining boundaries

- Desktop updater version is **0.1.49**. Install the matching hub, worker and web bundle together through the normal app update path; source changes do not modify an already-running process. Review the live policy and refresh model catalogs after updating. This release does not force remote-node updates, change live grants or require a PC reboot.
- Existing whole-file transfers, browser Full Access and question/approval attention improvements from v0.1.48 remain included. Upstream MyOwnMesh advertisement/route issues are not claimed fixed by this release.
- Linux remote-node packages remain available for amd64 and arm64, not a Linux desktop/full hub. Windows installers remain without Authenticode signing; macOS builds are ad-hoc signed and unnotarized. If Gatekeeper blocks an installed app, the existing manual workaround is `xattr -dr com.apple.quarantine /Applications/AllMyAgents.app`.

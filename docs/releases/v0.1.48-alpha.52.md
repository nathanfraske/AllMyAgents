# AllMyAgents v0.1.48-alpha.52

## Background whole-file transfers

- `remote_transfer_file` uploads or downloads a complete file in one agent request. The hub handles buffered asynchronous transfer, checksums, progress, cancellation and retained status; agents no longer need to shuttle repeated base64 chunks through chat.
- Progress updates a single stable timeline row, without reordering the sidebar on every buffer. Transfer bytes stay out of the journal and do not consume chat attachment storage. Publishing a downloaded file remains a separate action.
- Existing chat/device/root grants are checked throughout. Publication never overwrites a file, checksum mismatches cannot publish, and uncertain acknowledgements remain `outcome_unknown` instead of silently retrying a write.
- Version 1 supports regular files up to 256 MiB, four active transfers, existing parent directories and new destination paths. It requires a filesystem with hard-link support, such as NTFS or ext4. Directory trees, overwrite and automatic resume are not included.
- **Update both the controlling desktop hub and the remote node.** Old targets explicitly report that an update is needed before copying. An update is not a permission grant, and this release does not automatically update/restart remote nodes. Drain active jobs before an intentional service update; no PC reboot is required.

## Browser, questions and approval visibility

- An enabled browser in effective Full Access can navigate, click, open permitted tabs and download without repeating individual approval prompts on operator-origin turns. Separate browser, local-network, tabs and downloads grants remain enforced, including revocation before action commit. Safe/Edits and teammate-origin restrictions remain.
- Pending Codex questions have an attention dialog and a persistent way to reopen it. Dismissing the popup does not submit a default answer or skip the question; answer failures remain visible.
- The Overseer's chat shows requests actually routed to it for review. Explicit operator review guidance and requester-session scope are supported; eligible individual decisions require fresh payload-bound, one-use review tokens. Unknown/high-risk/destructive, self, expired, revoked and out-of-ceiling requests remain operator-bound. Arbitrary workflow file bodies are not declared safe by tool name.
- A positively identified transient Overseer connection failure can accept one fresh mail wake. Authentication, usage limits, refusals and unknown failures do not trigger replay loops.

## Remote access and storage fixes

- Shared devices and discovery failures are visible without confusing presence with ownership or route authority. Remote permission drafts survive equivalent periodic chat refreshes, and an unchanged offline grant no longer blocks adding another authorized testbed.
- Agents can inspect their own published-artifact inventory and request exact-item cleanup when it fills. Deletion requires approval and leaves an audit/tombstone; workspace originals, operator uploads and other chats are untouched. Browser download storage is separate.
- Late local durable-run output/completion is fenced after shutdown, preventing writes into a closed database. Shutdown does not invent a successful completion or cancellation.
- Integrates the existing reviewed Linux/Windows local-runner workflows; macOS and remaining platform gates retain their configured runners.

## Qualification and compatibility

- Local source qualification: 1,713 hub tests passed (one skipped), 811 web tests passed, hub typecheck/build and Svelte checks passed. Release CI and installed launch/repair gates remain required.
- The exact transfer engine copied and verified 32 MiB binary fixtures on granted Ubuntu and Windows hosts, including restart receipts, duplicate/no-overwrite rejection, checksum failure and abort. These were isolated test processes, not production daemon replacements or a claim of deployed cross-machine network throughput. Authenticated HTTP transfer and stable UI projection also have regression coverage.
- Temporary MyOwnMesh pipe permissions are not made permanent by this release. The remote transport/service must be reachable and paired independently.
- Desktop updater version increases to **0.1.48**. Linux remote-node packages remain available for amd64 and arm64; this is not a Linux desktop/full-hub or RISC-V package.
- Windows installers are not Authenticode-signed. macOS builds remain ad-hoc signed and unnotarized; if Gatekeeper blocks the installed app, run `xattr -dr com.apple.quarantine /Applications/AllMyAgents.app`.

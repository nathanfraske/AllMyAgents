# AllMyAgents v0.1.42-alpha.46

Released 2026-09-06.

## Scrolling and side panels

- Transcript wheel/touchpad listeners are now passive. Once detached from the latest message, repeated wheel
  input no longer forces synchronous layout reads on every sample. Follow-tail, jump-to-bottom and remount
  behavior retain their existing guards.
- Browser, GitHub/Diff, Runs and native-agent tabs now share one adjacent rail. Opening a panel moves the other
  tabs to the conversation's new edge instead of leaving them overlapping the drawer.
- The GitHub/Diff tab is available for checkout-backed chats even when only a working directory is recorded.
  Its existing exact-commit and comparison links open GitHub in the external browser.
- Runs is an icon with an active count and hover label, with no vacant slot between it and the other tabs.
  Active runs are grouped by project and labeled with their owning agent; completed runs remain collapsible.
  Separate bounded active/completed queries keep long-running work visible behind newer completed commands.

## Live activity and questions

- Durable run outcomes now attempt the ordinary acknowledged delivery path while the owner is working,
  rather than waiting unconditionally for idle. Rejected steering retains the notice for one idle follow-up;
  successful steering does not repeat that notice in the next turn. Existing authority boundaries remain intact.
- Native Codex web research appears in the activity log with search queries and open/find destinations,
  including sub-agent attribution. Existing Claude WebFetch/WebSearch activity is preserved.
- Codex request-user-input messages now use the existing durable question service through a provider-specific
  adapter, in both worker and in-process execution. Cards handle id-keyed answers, free text, restricted choices,
  masked secret input and blocking/nonblocking requests. Cancellation never invents an answer or permission grant.
- Claude keeps its distinct AskUserQuestion schema and answer encoding. The two providers do not share an
  invented combined protocol.

## Journal footprint and remaining investigation

SQLite's standard `journal_size_limit` now bounds retained spare WAL space to 64 MiB by default after a safe
reset. A reader holding a snapshot can legitimately keep a larger WAL until it releases that snapshot. There
is no forced truncation, reader eviction, deletion of durable history, or reduced durability.

The intermittent eight-second history-load timeout is **not yet resolved**. Sampled indexed queries on the
live multi-gigabyte journal were fast, but those measurements were warm local SQL reads, not a reproduction of
the complete failing request. This release does not claim that the WAL change fixes every history or UI stall.

## Verification

The fix pass includes regressions for passive wheel listener cleanup, follow-tail/detach/jump behavior,
active-run completion races, run ownership/grouping, web activity, provider-specific questions and pinned
SQLite reader safety. An isolated Chromium harness exercises the real transcript with 1,200 synthetic rows
and checks side-panel docking at 1200, 800 and 560 CSS pixels. No live operator session or personal browser is
used by that fixture.

Release publication is gated on the repository's cross-platform suites, native checks, credential/payload
audits and exact-tag Windows/macOS installed launch-and-repair verification. Detailed fix-pass evidence and
limitations are in [the investigation notes](../scroll-and-activity-fix-pass.md).

## Updating

After the release workflow completes, use **Settings → Check for updates**. The numeric application version
increases to **0.1.42**, so existing installations can discover it through the signed updater manifest. Publishing
this release does not restart a running app, service or operating system; installation remains an operator action.

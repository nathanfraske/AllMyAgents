# AllMyAgents v0.1.25-alpha.29

Released 2026-08-11.

## Purpose

This release makes the control plane easier to read without weakening its audit trail, closes the manager wake gap
when a worker finishes, and makes durable operator guidance survive resumed and compacted Claude/Codex conversations
without allowing a giant saved instruction or fleet roster to crowd the task out of context.

## Human-readable AllMyAgents activity

- Every current provider-neutral AllMyAgents tool now has a concise timeline phrase covering coordination, child and
  team management, durable runs, scoped team queries, memory, practices, browser actions, remote-device work, and
  Overseer operations.
- Labels use safe bounded arguments when they materially clarify the action: a teammate display name, run kind, file
  basename, browser hostname, selected query facets, or Overseer operation. Unknown future tools degrade to a readable
  humanized label rather than exposing an MCP identifier as the primary UI.
- Expanding an activity row reveals the exact technical tool name, serialized input, bounded result, and error state.
  Readability is therefore additive; it does not replace protocol-level evidence.
- Remote shell command arguments stay out of the collapsed label. Commands can carry tokens, passwords, or one-use
  authorization codes, so their exact bytes remain only in the deliberately expanded audit detail.
- Claude and Codex render the same logical tool action through one shared classifier, and grouped Codex summaries use
  the same label source as individual rows.

## Worker completion wakes the manager

- A managed worker entering `idle` is now an action-required lifecycle transition for its project manager. The manager
  wakes exactly once to collect the result, review it, report it, or assign follow-up work instead of waiting for the
  operator's next message.
- `started` and ordinary non-actionable lifecycle notices remain FYIs and continue to respect the high-context wake
  guard. Stall and error transitions retain their existing action-required behavior.
- The event remains hub-minted structural mail. A worker cannot self-author an attention flag or turn a teammate
  message into operator authority.

## Live scoped operator instructions

- The durable instruction store now returns applicable records with their scope provenance intact: global, vendor,
  project, account, then session. A more-specific record governs only an explicit conflict in its scope.
- Claude receives the current records through the supported Claude Code preset system append on every query, including
  resumed threads and Claude-created subagents. Codex receives the equivalent current records through thread developer
  instructions, with the existing post-compaction refresh path preserved.
- `CLAUDE.md` and `AGENTS.md` remain native continuity and audit layers, but the app no longer relies on either provider
  rediscovering a changed file inside an already-running conversation.
- Automatic model-facing operator context has one combined 8,000-character budget, not one budget per scope. Records
  that fit remain byte-for-byte exact. Oversized records share the budget fairly; their beginning and end remain,
  their middle is explicitly omitted, and a stable SHA-256 prefix identifies the durable source record.
- The hub never asks a model to summarize authoritative operator rules. A semantic summary could silently remove the
  one exception or safety clause that matters. The omission marker instead says the missing clause was not applied and
  directs the operator to split or shorten the saved scope when that detail is needed.
- The complete exact record remains in the durable AllMyAgents instruction store and Settings UI. Unbounded legacy
  content is no longer copied in full into the native instruction file, which would have reintroduced the same context
  poisoning through a second path.

## Hard-bounded live topology

- Manager, worker, and Overseer topology already excluded chat prose, task bodies, tool output, paths, and teammate
  messages. This release adds the missing serialized-character boundary: the complete topology frame can never exceed
  8,000 characters.
- If count-bounded agents, teams, projects, or intervention facts still serialize too large, the hub removes array
  tails deterministically while retaining valid JSON and scalar summaries. A `lengthGuard` reports the original size,
  maximum size, and exact collections from which rows were omitted.
- An emergency fixed-size frame handles a pathological oversized header without reusing the offending dynamic text.
  Long imported or mesh-qualified scope identifiers are also bounded before entering headings.
- Agents are explicitly told to use live scoped status, list, peek, or query tools for omitted records. A bounded
  snapshot is orientation data, never authorization or proof of current fleet state.

## Context-engineering rationale

- Prompt caching changes cost and latency but cached tokens still occupy the context window. It is not treated as a
  defense against instruction dilution.
- The protected rules and topology have separate ceilings so a large fleet cannot evict operator invariants and a
  large saved rule cannot evict live fleet orientation.
- Stable, compact invariants stay in the provider-native instruction boundary; detailed changing state remains
  discoverable through bounded tools. This follows the vendors' documented preference for small high-signal context
  and just-in-time retrieval.

## Known boundaries

- The hub-managed instruction regions are bounded, but repository-authored `CLAUDE.md`/`AGENTS.md` content outside
  those regions belongs to the project and is not silently rewritten or truncated by AllMyAgents.
- When an operator scope exceeds the automatic-context budget, the full record remains durable but is intentionally not
  claimed as fully active model context. Split genuinely independent requirements into concise scopes rather than
  treating a long policy document as an always-on prompt.
- Claude's installed SDK exposes a dynamic cache boundary for a fully custom system prompt, not for the Claude Code
  preset append used by the app. This release keeps the vendor's native Claude Code prompt rather than replacing it for
  a speculative cache optimization.

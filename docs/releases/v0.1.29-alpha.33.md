# AllMyAgents v0.1.29-alpha.33

Released 2026-08-20.

## Purpose

This release repairs a provider-output failure that could repeatedly interrupt a long-lived Codex manager, removes
a hidden second configuration gate between a manager's explicit remote-device grant and an existing project
checkout, and carries the pending route-recovery and shared-testbed-toolchain fixes from the post-alpha.32 live pass.

## Long Codex conversations stay isolated

- Codex `thread/resume` now negotiates the provider's metadata-only resume capability and requests
  `excludeTurns: true`. Provider continuity still resumes, while AllMyAgents remains the owner of the lossless,
  paged conversation timeline.
- Previously, Codex could return every persisted turn and item in one newline-delimited JSON response even though
  AllMyAgents did not consume that duplicate history. On a sufficiently old manager, Node's `readline` accumulator
  reached V8's string limit and terminated the shared worker with `RangeError: Invalid string length`.
- The app-server transport now frames UTF-8 as bounded bytes rather than repeatedly concatenating an unterminated
  JavaScript string. Fragmented multi-byte text, CRLF, multiple frames, and final unterminated frames retain their
  exact behavior.
- An oversized or malformed frame rejects pending calls, records a bounded `codex/protocol-error`, and restarts only
  that Codex app-server child. The shared worker and unrelated Claude/Codex sessions remain available.

## Remote grants and project locations

- A terminal grant to an exact remote root remains the authority boundary. Project preparation no longer requires
  the operator to repeat that same decision in a separate, hard-to-find project-location menu.
- On first preparation the hub inspects the granted root. If it is a complete, clean checkout with the same
  credential-free repository identity as the clean primary checkout, it is registered as a remote replica and then
  synchronized to the primary's exact named revision.
- The registration and subsequent synchronization are separately journaled and retain project, session, agent,
  replica, site, root, and base-commit attribution.
- A generic machine root such as WSL `/home` remains available immediately for remote commands and durable runs. It
  is not source code, is never promoted into a project replica, and now returns `PROJECT_CHECKOUT_REQUIRED` with an
  explicit explanation instead of the misleading `REPLICA_NOT_ATTACHED`/missing-grant report.
- Manager and Overseer methodology now states that distinction directly so existing agents do not send the operator
  back through an unnecessary grant loop.

## Paired route recovery and diagnostics

- Fleet routing checks the actual mapped `/api/health` endpoint and replaces a mapped-but-dead Site route once before
  classifying a paired hub offline.
- Targeted resolution can recover one paired device without sweeping or remapping the rest of the roster.
- Remote-device and testbed surfaces preserve actionable causes: device absent from the signed roster, no Site map,
  mapped route with no listener, unhealthy HTTP response, route timeout, or degraded MyOwnMesh/AllMyStuff control
  plane. An empty fleet and a failed discovery plane no longer look identical.
- The Windows ACL diagnosis now points to the durable repair—the service-owned pipe must grant the interactive user
  full-duplex access—rather than advising the whole app to run elevated.

## Shared lightweight-testbed toolchains

- Linux system testbeds reserve `/opt/allmyagents-toolchains` for reusable, world-readable compiler payloads and add
  the shared environment to both the service and ordinary login shells.
- Rust uses a shared `RUSTUP_HOME`; writable `CARGO_HOME`, registry, source, and package caches remain per-user. This
  keeps an SSH fallback usable without turning unrelated accounts' writable caches into shared mutable state.
- Existing `/opt/rust` RISC-V installations remain discoverable, and a private service-account Rust toolchain can be
  reconciled into the shared prefix without making `/root` readable.
- Remote environment inspection reports resolved executable paths and whether a tool came from the ordinary shell,
  the shared toolchain prefix, or the service account.
- The lightweight node now reports its own running Node executable directly. Service and CI environments no longer
  misreport Node as unavailable merely because the launcher used an absolute path and omitted it from `PATH`.
- Elevated transient run units inherit the same bounded toolchain environment and a predictable `0022` umask.

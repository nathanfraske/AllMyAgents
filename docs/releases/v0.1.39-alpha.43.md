# AllMyAgents v0.1.39-alpha.43

Released 2026-09-01.

## Purpose

This release removes the remaining database scan behind cold chat-history timeouts and adds two compact workspace
drawers for the work an agent is doing now: its Git diff and its durable runs.

## Bounded cold history

- Session history now reads a dedicated `(session, sequence)` projection containing only transcript-renderable
  events. Streaming reasoning, command-output, and message deltas never enter that projection.
- A long manager chat can therefore find its latest 40 meaningful events directly instead of walking backward
  through hundreds of thousands of irrelevant rows in the multi-gigabyte event table.
- The projection is crash-resumable, advances in the existing bounded post-ready maintenance child, and is kept
  exact by insert/delete/frontier triggers once current. Upgrading never performs a full scan on the boot path.
- Externalized payload bodies remain asynchronously hydrated with the existing bounded concurrency and byte
  budget. Oversized individual events retain the explicit placeholder and lossless older-page cursor.
- While an upgraded journal's new projection is still catching up, the API reports the existing retryable
  "history index is building" state instead of blocking the hub main thread until the eight-second client bound.

## Working diff drawer

- A new Diff tab sits below the isolated-browser control in every Git-backed conversation.
- It compares the complete live checkout—including committed, staged, and unstaged changes—against the recorded
  base, `main`, or another operator-entered Git revision. Untracked files are listed explicitly.
- The base is resolved to an exact commit before comparison. Git runs with external diff and text-conversion
  helpers disabled, bounded output, and a ten-second process deadline.
- GitHub origins expose direct buttons for the exact head commit and base-to-head comparison in the system browser.
- The patch is capped at 1 MiB with a visible truncation boundary; file status remains available independently.

## Project runs drawer and shared logs

- A new Runs tab shows queued/running durable work, status, owner, local/remote target, elapsed time, command, and
  retained output. Terminal work moves to a collapsed Completed section rather than consuming live-panel space or
  losing its audit record.
- Any live member of a project can now use `inspect_runs` to read the project's durable run state and logs,
  including manager-started and sibling-targeted runs. This fixes the coordination gap where a worker could not
  inspect the build it was expected to verify.
- Read authority is separate from mutation authority: workers still cannot start or cancel project runs. Those
  operations retain the existing project-manager/Application-Overseer gate and resource leases.
- HTTP/UI reads use the same project-scoped authority and the existing 64 KiB-per-stream log pages.

# AllMyAgents v0.1.34-alpha.38

Released 2026-08-24.

## Purpose

This release activates the inexpensive Manager Assistant that was present but effectively dormant, then removes
several sources of coordination bloat measured in a long-running Codex project manager. The main manager keeps
decomposition, judgment, integration, and reporting; routine bounded approval triage and event coalescing stop
consuming full-context turns.

## Manager Assistant

- New managers default to the assistant when child-approval authority is enabled. Existing approval-capable
  managers whose setting was never configured are upgraded on the ordinary durable capability path.
- An explicit disabled setting is a durable operator choice and is never overwritten by an upgrade.
- Codex managers prefer the account's advertised Spark model at low effort; Claude managers use Sonnet 5 at low
  effort. The evaluator remains stateless and hidden, has no tools or writable project access, and is serialized so
  an approval burst cannot create a model swarm.
- The deterministic live hierarchy, operator capability ceiling, and risk floor remain authoritative before and
  after model evaluation. Uncertainty, unavailable accounts, provider failure, and broader risk still wake the
  manager or escalate normally.
- Decision cards are labeled **Manager Assistant** in the requesting worker's transcript and retain the complete
  audited decision explanation and risk classification.

## Bounded coordination

- Each worker lifecycle event remains an individual durable bus row, while sibling changes within a short window
  produce one manager pulse instead of one provider steer per worker.
- Idle, stalled, and errored workers remain actionable wakeups. Routine starts and stops are collected without
  interrupting an already-running manager turn.
- The generated manager contract explicitly forbids duplicating assistant decisions, rereading the same cursor,
  polling unchanged children or runs, and keeping a provider turn alive with wait or sleep loops. When there is no
  dispatch, decision, bounded inspection, integration, or exact blocker to report, the manager yields to the hub.
- `query_team` now defaults to 20 records and is capped at 100. Transcript peeks default to 40 exact events and
  expose an explicit bounded page size and cursor.
- The common MCP server header was reduced to the small trust and routing invariants. Complete operating
  methodology remains in the provider-native per-turn contract instead of being repeated across all 44 tools.

## Honest Codex token telemetry

- The modern Codex thread-cumulative counters now retain input, cached input, output, reasoning output, and total
  tokens.
- Thread-lifetime totals are stored separately from the latest request's context occupancy, preventing a large
  cumulative number from being presented as one request or one app turn.
- `/usage` shows the provider-thread total and cached-input ratio when the provider supplies them. This is direct
  provider telemetry; semantic workload-versus-coordination attribution remains an analysis rather than a
  fabricated exact counter.

## Verification

- Focused hub contracts cover legacy upgrade, explicit opt-out preservation, inexpensive model selection,
  approval boundaries, simultaneous lifecycle coalescing, routine no-wake behavior, bounded MCP instructions, and
  modern Codex token envelopes.
- Web store and manager-setup contracts cover cumulative-token separation and the default-on assistant setting.
- Hub and web TypeScript/Svelte checks and production builds pass.
- The complete release workflow re-runs the installed launch-and-repair gate, credential firewall, platform builds,
  updater version guard, and signed artifact publication at the exact tag.

# AllMyAgents v0.1.41-alpha.45

Released 2026-09-04.

## Purpose

This hotfix makes account-scoped rollout models such as GPT-6 Astra appear as soon as the signed-in Codex account
advertises them, even when that provider catalog is refreshed after the AllMyAgents UI has already loaded.

## Live account catalog refresh

- The UI now reconciles local account catalogs alongside its existing five-second authoritative session refresh.
- Session and account reads execute concurrently with independent bounded failure handling. A slow catalog read
  cannot hold back session status, and a failed session read cannot discard a successfully refreshed catalog.
- The account list is replaced only with the latest local profile projection while existing fleet profiles remain
  intact.
- Provider entitlement remains the boundary: `gpt-6-astra` appears only on the exact profile whose current
  `model/list` cache advertises it.

## Root cause

The provider may write `models_cache.json` when its first app-server turn starts. Previously, AllMyAgents fetched
profiles only during UI bootstrap and selected account-management actions. When the cache changed after bootstrap,
the model picker retained the earlier snapshot until a page reload even though the hub could already see Astra.

## Verification

- The installed Codex B profile was observed advertising `gpt-6-astra` in its current provider cache.
- A regression replaces a boot-time Codex catalog with a later Astra-bearing catalog and proves the live store
  adopts it without a reload.
- Focused store/catalog tests pass (146 tests).
- The complete web suite passes (78 files, 738 tests).
- Svelte check reports zero errors and zero warnings, and the production web build passes.

# AllMyAgents v0.1.35-alpha.39

Released 2026-08-25.

## Purpose

This release closes the missing lifecycle bridge between durable execution and manager coordination, and removes
the remaining long-conversation delays around first paint, manager steering, and manual scroll position. A manager
could start a build or test, yield while it ran, and remain idle forever after the run finished because the hub
persisted the terminal run record but never turned that result into manager mail or a new turn.

## Durable run continuation

- Every successful, failed, cancelled, or outcome-unknown durable run now creates one action-required inbox item
  for the session that started it.
- The continuation contains the exact run id, command summary, exit code or signal, and a bounded failure detail.
  The manager is directed to use `inspect_runs` for retained cursor-paged logs rather than copying a large compiler
  transcript into context.
- An idle owner is woken immediately, including when its context is large. If a terminal result arrives while the
  owner is already active, it remains durable and starts a fresh bus-origin continuation after that turn becomes
  idle; it is not injected as a late steer into work that may already be finalizing.
- The behavior is provider-neutral and applies to local and granted remote runs.

## Restart and duplicate safety

- Each run stores whether its terminal continuation was acknowledged. A successor hub replays a terminal result
  whose state committed before its inbox delivery could be acknowledged.
- Inbox insertion has an idempotency receipt keyed to the exact run. A crash between inserting the message and
  marking the run acknowledged cannot create a duplicate on recovery.
- Terminal runs from older releases are marked acknowledged by the additive schema upgrade so installing this
  version does not wake managers for historical work.
- A transient delivery failure leaves the result retryable while emitting bounded diagnostics rather than a new
  journal row every maintenance interval.
- `outcome_unknown` retains its stronger warning: inspect the existing run and never retry it blindly because the
  target command may have completed.

## Conversation responsiveness and steering

- A normal history request now seeds the pane with at most 40 semantic events or 256 KiB. The hard API ceiling
  remains wider for diagnostics, and every older event remains available through lazy upward paging.
- The current 2.5 GB production journal was measured before this change: twenty successive manager-history pages,
  including several near the prior 512 KiB ceiling, returned in 67â€“474 ms. That ruled out the current async blob
  store as the remaining delay and focused the fix on payload-to-DOM work in the WebView.
- A history request has one honest eight-second bound. The app no longer turns that into a hidden 28-second wait by
  automatically issuing a second twenty-second request; it keeps the error distinct from an empty conversation and
  offers an explicit Retry.
- A message typed while a manager is `starting` is persisted with its delivery intent and promoted to a live steer
  immediately when the turn becomes `active`. Ordinary after-turn queue entries keep their existing semantics, so
  replayed status changes cannot accidentally send them.
- Wheel and touch intent clear the live-edge pin before WebView's delayed scroll event. New manager messages can no
  longer pull the transcript to the bottom in the small race between the gesture and that event.

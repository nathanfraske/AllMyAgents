# AllMyAgents v0.1.27-alpha.31

Released 2026-08-14.

## Purpose

This is a journal-durability and direct-testbed recovery release. It removes the unbounded I/O loop that could
read and rewrite hundreds of gigabytes while producing no backup, makes an over-size journal converge through
ordinary bounded maintenance instead of a machine-specific cleanup migration, stops the supervisor from paying
for the same database proof on every respawn, and repairs direct-only MyOwnMesh actions whose signatures changed
when the relay reordered JSON map keys.

It also completes the application-level Overseer paths that were documented but structurally project-gated:
durable ad-hoc runs, machine maintenance elevation, urgent handoffs, and a stronger current-session methodology.

## Bounded, lossless journal storage

- Strings at or above 64 KiB are stored in a crash-safe content-addressed blob store. Publication writes and
  flushes an immutable blob before atomically committing its SQLite reference, so an interruption may leave an
  unreferenced blob but cannot publish a row pointing at bytes that never reached disk.
- New appends preserve the exact in-memory event delivered to live clients. Replay, cold baselines, indexed event
  reads, and lazy history hydrate and hash-verify the original bytes; unreadable blobs produce explicit evidence
  rather than fabricated content or a silent skip.
- Existing inline payloads converge through the same ordinary maintenance path in bounded, resumable batches.
  The projection cursor advances transactionally with each compare-and-swap row rewrite and survives interruption.
- Resident SQLite has an explicit 2 GiB default target. Legacy roots convert to incremental auto-vacuum only after
  their exact payload projection is current; later cycles reclaim at most 16,384 pages. Already-compliant roots do
  no physical rewrite.
- The target and snapshot policy are configurable with `AMA_JOURNAL_SQLITE_TARGET_BYTES`,
  `AMA_JOURNAL_SNAPSHOT_KEEP`, and `AMA_JOURNAL_SNAPSHOT_MAX_BYTES`.
- Snapshot and strong-recovery retention run on every post-ready maintenance cycle, retain the newest verified
  evidence, default to two generations under a 4 GiB budget, and remove complete SQLite families rather than
  leaving `-wal`, `-shm`, or partial sidecars behind.
- The app never deletes the only copy of unique transcript bytes to pretend a finite storage budget was met. If
  retained exact history itself exceeds an operator's allowance, maintenance reports that honestly; an explicit
  history-retention policy is the remaining product boundary.

## Hot-database backups that converge

- The backup worker opens a dedicated read-only connection, begins a transaction, and performs a real read before
  invoking SQLite's online backup API. That pins one immutable WAL generation while the live hub continues writing.
- Copying aborts after more than two observed restarts, more than 3x the source page work, or ten minutes. A second
  parent-process deadline kills a child if the native addon stops delivering progress callbacks.
- A doomed generation cannot overlap the next scheduled attempt. Backup ownership, exclusive payload/storage
  maintenance, activation, blue-green handoff, and shutdown all preserve one in-flight generation at a time.
- Progress reports elapsed time, source/physical pages, restart count, transferred bytes, and whether the read
  snapshot was pinned. Failure removes the unpublished partial and retains every verified generation.
- Size-aware cadence reduces full-snapshot frequency as the journal grows. Verification and lineage publication
  remain explicit protected phases after the bounded copy completes.

## Startup and supervisor stability

- Ordinary boot uses `PRAGMA quick_check`; the full `integrity_check` remains on the isolated suspicion/recovery and
  verified-backup paths instead of occupying the readiness boundary on every start.
- A successful preflight produces an exact identity receipt covering the journal family and recovery generation.
  The same supervisor may reuse it only while that identity remains byte-for-byte unchanged; a supervisor restart
  or any identity change re-verifies.
- Preflight runs in a worker that renews the supervisor liveness lease, so native SQLite work cannot starve the
  parent-thread heartbeat that proves the hub is still progressing.
- Heavy Overseer/team instruction and grant rematerialization now runs one session at a time after the public
  listener is ready, yielding between durable units. The prior synchronous sweep was the measured main-thread stall
  between profile and session restoration.
- Replica attribution remains synchronous at the public-owner admission boundary. The full-suite audit caught and
  fixed a race in which an otherwise-ready restored agent could begin a remote durable run before receiving its
  project-replica id.
- Backup and journal maintenance are mutually exclusive and defer to one another rather than multiplying disk I/O.

## Direct MyOwnMesh and lightweight testbeds

- Direct envelopes now sign recursive canonical JSON after normalizing through the same JSON serialization boundary
  used on the wire. Map insertion order, including nested maps, can no longer invalidate a legitimate HMAC when the
  MyOwnMesh relay deserializes and reserializes it.
- This protocol change requires both endpoints to update together. The release packages the hub and lightweight
  node from the same source revision; an old endpoint intentionally cannot authenticate a new envelope.
- `MYOWNMESH_HOME` now resolves its control socket once instead of appending `daemon.sock` twice.
- A lightweight node fails startup honestly when no event socket opens and keeps a referenced event-loop handle
  while running; it can no longer print `status: running` and exit zero immediately afterwards.
- MyOwnMesh-only nodes use the daemon's real roster operations, advertise the capabilities required for discovery,
  and no longer depend on an `owned_roster` operation that the daemon does not implement.
- Automated deployment defaults to scoped access. Elevated machine profiles remain explicit and carry a
  blast-radius warning; fleet-wide trust exchange is opt-in rather than silently equating roster membership with
  root or administrator access.
- Deployment performs reciprocal, one-use, short-lived pairing with the node's device token. Status polling is
  read-only after the one-time mutation, and RISC-V architecture aliases normalize consistently for future payloads.

## Application Overseer and actionable coordination

- The Overseer can start a durable local run with an explicit absolute working directory even though it is not
  project-bound. Resource leases, retained logs, provenance, exit state, cancellation, and `outcome_unknown`
  semantics remain identical to project runs.
- Elevation has a separate operator-owned application/machine policy. Service, process, registry, and other
  non-project maintenance no longer require a fake project id or inherit an unrelated repository root.
- Machine elevation remains deny-by-default: direct operator turn, enabled policy, blast-radius analysis, dedicated
  approval, operating-system elevation, timeout, cleanup, and journaled result are all still required.
- Actionable manager/Overseer messages can wake one intended recipient through audited `attention_required`
  semantics. Routine FYIs remain queued; urgent reach changes neither the bus origin nor the recipient's authority.
- Current and future Overseers upgrade in place to capability contract v17. The generated methodology now explains
  when to use operator-authority messaging instead of the teammate bus, how to state evidence at its measured
  strength, how to retract an incorrect relay, and that the Overseer delegates shipping code to the owning agent,
  then inspects and verifies it.
- Managers receive the same explicit task accounting and durable-run methodology without waking idle chats into a
  reminder loop.

## Production-scale evidence

The release candidate was tested against a separate copy of a verified production snapshot:

- before: 3,207,106,560-byte SQLite database, 994,617 events, 54 sessions, 782,985 pages, `quick_check: ok`;
- projection: 5,241 rows and 1,492,584,196 logical bytes externalized into 1,375,634,521 unique blob bytes;
- after ordinary convergence: 1,509,273,600-byte SQLite database, 54 sessions, incremental auto-vacuum enabled,
  `quick_check: ok`;
- compliant next cycle: 5.5 seconds, identical database size/page/freelist and no new enforcement rewrite;
- first isolated preflight: 6.5 seconds with seven liveness renewals;
- unchanged same-supervisor preflight: 0.21 seconds with the content scan skipped by exact identity receipt.

The test copies were removed afterwards. No live journal, backup, recovery root, or running incident-reproduction
worker was changed by the measurement.

Use **Settings → Check for updates** once the exact-tag verification and signed assets finish publishing. The
release page will provide the Windows MSI/NSIS installers and Apple Silicon/Intel macOS downloads.

For macOS, the supported alpha install command remains:

```sh
curl -fsSL https://raw.githubusercontent.com/nathanfraske/AllMyAgents/main/scripts/install-macos.sh | bash
```

Windows SmartScreen and macOS notarization warnings retain the documented alpha behavior.

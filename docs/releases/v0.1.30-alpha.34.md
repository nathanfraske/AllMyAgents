# AllMyAgents v0.1.30-alpha.34

Released 2026-08-20.

## Purpose

This release makes remote testbeds practical for project managers: one explicit operator authorization carries
through to real concurrent work, the project is prepared automatically on the selected machine, remote chat traffic
stays bounded, and transient health responses no longer destroy a working route. It also adds durable all-GitHub
controls that behave consistently for Claude and Codex.

## Full testbed authorization means full access

- **Authorize testbed** is now the primary action in both chat and device settings. It grants the selected chat every
  read, write, and terminal capability actually advertised by that node, across its available Windows drive roots,
  WSL2 distributions, Linux filesystem, or macOS filesystem.
- The exact persisted chat/device/root grant is standing operator authority. Manager- and teammate-origin turns can
  consume it directly without asking for another project association or command approval.
- The old one-active-terminal-command fence is removed. Independent commands and file operations can run normally in
  parallel; durable runs still serialize only when their declared resource key requires it.
- Pairing by itself still grants no file or terminal access. The broad authority begins only when the operator chooses
  **Authorize testbed**, and it remains revocable from the same grant surface.
- The application Overseer can assign a complete advertised testbed to a manager or other chat with
  `authorize_remote_testbed`; the advanced root/capability editor remains available for deliberately narrower grants.

## Projects prepare themselves on remote machines

- A project chat immediately inspects the preferred full-capability root after authorization. If the root is already
  a clean checkout of the same repository, AllMyAgents attaches it without another prompt.
- A broad machine root that is not a repository receives a deterministic app-owned checkout under
  `.allmyagents/projects/`. The target clones non-interactively using its own Git credentials, verifies the safe
  credential-free repository identity, fetches the named primary branch, and checks out the exact published commit.
- Existing dirty or unrelated repositories are never overwritten. They produce a clear conflict while the underlying
  machine grant remains usable.
- Every important remote project run repeats the parity check before execution, so a manager can start a build or test
  without manually synchronizing the device first. Reservations, replica identity, commit, actor, and result remain
  journaled.

## Stable and quieter remote connections

- Background fleet observation no longer replaces a Site mapping because a peer hub returned HTTP 503 or responded
  slowly. Either response proves the byte route exists; only connection refusal or a transport failure can qualify a
  mapping for repair, and route mutation during ordinary polling is removed entirely.
- An authenticated live remote WebSocket is treated as stronger evidence than one transient health response, avoiding
  the all-agents-offline flicker seen while a peer was booting or busy.
- Remote WebSockets still carry compact project, session-state, approval, notification, profile, and usage updates,
  but hydrate transcript/tool payloads only for remote chats currently visible in a pane. Switching panes updates the
  subscription without replaying unrelated agents, eliminating multi-megabit idle transcript transport.
- Filtered replay advances its durable cursor over skipped rows, so a noisy hidden session is not rescanned forever.
- Route failures retain their distinct roster, mapping, listener, unhealthy-hub, timeout, and control-plane causes.

## Turn delivery no longer waits behind stale activity

- When a live steer loses a race with turn completion, the hub now asks the provider for its exact live-session state.
  If the provider is idle while the durable record is stale-active, the hub corrects the record and starts one fresh
  queued turn.
- The recovery is exactly-once and does not reinterpret turn provenance or retry an ambiguous in-flight mutation.

## GitHub authority that persists for both vendors

- Chat permissions include **Allow all GitHub automation for this chat**; project settings include the same aggregate
  control for every manager and worker in the project.
- The control expands to the four independently enforced capabilities: pull-request work, merges, workflow runs, and
  repository pushes. Clearing it revokes the same set.
- Claude `gh`/GitHub operations and strictly classified Codex GitHub connector elicitations consult the same scoped,
  operator-owned policy. Unknown tools, repositories, connector operations, and explicit ask rules continue to fail
  closed rather than inheriting a broad plugin-level allow.

## Provider instructions and existing teams

- Overseer capability contract v23 and manager-team contract v9 explain the one-action testbed workflow, standing
  remote authority, normal concurrency, automatic project parity, and the advanced narrow-grant escape hatch.
- Existing Overseers, managers, and workers receive the updated generated contract at their next protected turn; no
  replacement conversation or manual instruction rewrite is required.
- Manager live state now includes exact remote grants and prepared replica paths/revisions, so compaction does not turn
  the topology back into stale prose.

## Verification

- Complete hub and web Vitest suites pass with zero failures.
- Hub TypeScript typecheck passes; Svelte check reports zero errors and zero warnings.
- Focused remote execution, fleet routing, replay filtering, manager/Overseer authority, project replica, turn-steer,

- The release preflight additionally stages and audits both runtime payloads, builds the web distribution, and runs
  Rust check and strict Clippy before the tag is published.

## Known external boundary

The app now preserves a healthy Site route and reports direct-lane permission failures accurately. The Windows
service-owned MyOwnMesh control-pipe DACL is created outside AllMyAgents; granting the interactive user full-duplex
access belongs to the MyOwnMesh/AllMyStuff backend rewrite and is not papered over by elevating this app.

## Updating

Use **Settings → Check for updates** after the exact-tag workflow finishes. The release page provides Windows MSI/NSIS
installers and Apple Silicon/Intel macOS downloads.

Windows SmartScreen and macOS notarization warnings retain the documented alpha behavior.

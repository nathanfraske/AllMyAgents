# AllMyAgents v0.1.17-alpha.20

Released 2026-08-04.

## Purpose

This release makes project-manager teams durable and switchable, gives the operator exact code-change
provenance, removes two scale-driven maintenance stalls, and repairs account sign-in so a failed provider flow
cannot immobilize the application. It also makes local Codex browser OAuth the normal no-terminal path while
retaining device authentication as an explicit remote/headless fallback.

The complete feature and fix log for the preceding Site-free remote-control cut has also been restored to the
top-level changelog and remains in `docs/releases/v0.1.16-alpha.19.md`.

## Durable manager teams

- Every project manager now owns a durable list of team generations with stable team IDs, names, creation and
  activation times, and optional preset provenance. Existing managers migrate idempotently to a default team.
- The manager tool surface can list, create, rename, and activate teams. Creating or activating a team stashes
  the previous lineup without deleting its chats, worktrees, commits, or audit history.
- A running outgoing team must be interrupted explicitly before a switch. The hub revalidates manager state
  after each asynchronous stop, preventing a concurrent edit from being overwritten by a stale activation.
- Team changes are serialized per manager. Incoming worktrees are reopened before the active pointer changes,
  and the pointer plus lifecycle events commit in one journal transaction after external effects succeed.
- New child sessions inherit the exact active team ID and display name. The manager capability contract and
  worker protocol carry those identities without relying on mutable labels.
- The sidebar groups manager children into independently expandable active and stashed team folders. A stashed
  team's lineup stays inspectable without presenting it as currently running.
- Manager setup and project views expose the current team contract and retain existing manager configuration
  rather than requiring the operator to recreate the project.

## Exact code-change provenance

- Project activity reports immutable agent ID/session ID, manager ID, team ID/name, branch, worktree, changed
  files, base/main relationship, and commits that are reachable from that agent's checkout but not main.
- Commit subjects are bounded, stripped of control characters, and kept next to their exact hashes. The UI no
  longer treats a mutable display name as authorship evidence.
- Shared project checkouts are called out as an attribution boundary: when multiple agents operate in the same
  checkout, the app reports the ambiguity instead of claiming that one agent authored every working-tree byte.
- Historical team snapshots remain visible after a checkout becomes temporarily unavailable. Inspection
  failures fall back only to the last trustworthy cached result and remain visibly tied to the prior observation.

## Bounded historical Git inspection

- Active managed worktrees continuously seed the attribution cache while they are already being inspected.
- Stashed worktrees refresh at most every five minutes instead of every 30-second UI poll.
- Each poll starts no more than two historical refreshes, preventing dozens or hundreds of stashed teams from
  creating a Git-process burst that competes with the hub, renderer, and live agents.
- Tests prove the second poll can serve a preserved historical snapshot after the disposable checkout is gone.

## Large-journal startup and maintenance

- Startup emits measured phase timing for journal validation, session projection, listener ownership, and
  deferred maintenance, so a safe database check is shown as loading rather than an unexplained disconnect.
- Conservative orphan-worktree cleanup now starts only after the public listener is serving. A one-minute
  eligibility grace protects a worktree whose agent has just exited or whose session is still materializing.
- The cleanup remains fail-closed: dirty worktrees, unique commits, authored instructions, corrupt indexes, or
  Git answers that cannot be proven safe are kept and named for operator review.
- Journal condensation's correlated selector now gets lazy composite indexes matching its session/type/sequence
  access path. On a large journal it can advance within the bounded maintenance window instead of spending the
  whole interval rescanning and committing zero work.
- The selector scale regression uses a measured ceiling large enough for a loaded Windows runner while still
  failing the former quadratic access path.
- Full SQLite integrity validation remains a boot safety boundary. This release exposes that cost and removes
  avoidable work around it; it does not trade corruption detection for a cosmetically faster status transition.

## Codex authentication and app responsiveness

- The default Codex method launches `codex login`, the documented browser OAuth flow for a local computer. No
  device code is generated or entered in a terminal, chat composer, or hidden console.
- Device authentication is a separate **Device code (remote or headless)** option that launches
  `codex login --device-auth`. The app displays the provider URL and one-time code, offers a copy action, and
  explicitly says that the code is entered on the linked webpage.
- The UI explains that device-code authorization must first be enabled in personal ChatGPT security settings or
  by a workspace administrator. A device-code rejection therefore leaves browser OAuth immediately available.
- Command construction was checked against the installed `codex-cli 0.145.0` help and the current official
  OpenAI authentication guide. Regression fixtures cover both command shapes and the current OAuth/device output.
- Durable login attempts record their authentication method. Pre-upgrade Codex attempts remain correctly
  interpreted as device attempts, and idempotency keys cannot be replayed across providers or login methods.
- The hub launch and polling APIs remain bounded to eight seconds. Native URL opening has a three-second ceiling;
  completion closes the reserved browser target before account refresh; and roster refresh happens in the
  background after credentials are already declared durable.
- Spawn failures, provider rejection, malformed output, polling errors, cancellation, and timeouts all leave the
  Settings modal closable and return its controls to a retryable state. A failed sign-in can no longer lock the
  account pane or the rest of the application.

Official behavior references:

- OpenAI Codex authentication: <https://developers.openai.com/codex/auth>
- Installed CLI contract checked with `codex login --help` (`codex-cli 0.145.0` in the release environment)

## Compatibility and truth boundaries

- Existing projects, manager sessions, vendor conversations, account bindings, and teamless child records migrate
  in place. Team switching does not rewrite history or claim ownership of commits based only on Git author text.
- Physical SQLite shrinking is not automatic. Reclaiming file-system bytes can require exclusive disk headroom;
  normal condensation instead makes freed pages reusable inside the journal.
- Orphan cleanup deliberately prefers leaked disk space over deleting uncertain work. The workspace-size warnings
  and operator maintenance surfaces remain the recovery path when Git cannot prove a checkout disposable.

# AllMyAgents v0.1.36-alpha.40

Released 2026-08-27.

## Purpose

This release fixes a shared-checkout identity ambiguity that could leave a project manager unable to message or
start its workers, removes another cold-history main-thread stall, and clarifies team hierarchy throughout the UI.
It also keeps backup protection truth separate from live hub reachability so a warning cannot make an otherwise
responsive hub and its remote routes appear unavailable.

## Exact manager and worker attribution

- Each app-owned Codex thread now receives a thread-scoped AllMyAgents MCP configuration containing its exact
  hub-issued session id. The binding is applied on thread creation and resume, and reasserted after compaction.
- The hub validates the bound session against the live provider, account, working directory, and lifecycle before
  accepting a tool call. An invalid binding fails closed and is journaled.
- This removes the old unique-account-plus-directory guess. A manager and several workers can intentionally use the
  same Codex account and shared checkout while `send_message`, `assign_child_task`, `query_team`, `child_status`,
  approval decisions, and durable-run inspection remain attributable to the correct conversation.
- Rolling compatibility remains bounded: an older thread without the exact binding may still use the conservative
  unique-session fallback until its next managed resume.

## Responsive history and truthful hub health

- Bounded WebSocket replay now estimates decoded JSON size from content-addressed blob metadata before any blob is
  read. A tiny SQLite pointer to a large cold string therefore cannot bypass the byte budget and trigger thousands
  of synchronous disk reads on the hub thread.
- The exact encoded frame is still checked after the bounded working set is hydrated, preserving the transport
  ceiling even when JSON escaping makes the final representation larger than its metadata estimate.
- Conversation history keeps its async, concurrent blob hydration and explicit Retry path. An individual retained
  event that exceeds a history page is represented by one marker explaining that the surrounding conversation
  loaded normally, rather than looking like the whole transcript failed.
- A booted listener returns healthy reachability even while journal backup protection reports a degraded or
  settling state. The warning and exact backup error remain in `/api/health`; only actual boot unavailability is
  HTTP 503. Supervisor promotion continues to enforce backup ownership independently.
- Journal-maintenance progress guards are cleared at every terminal child result so a completed, failed, or
  intentionally deferred condensation cannot later be misreported as observation loss.

## Conversation and hierarchy polish

- The live-edge scroll pin now follows output whenever the transcript is at its bottom, including after the
  operator manually returns there. Wheel, touch, and ordinary upward scrolling detach it only while reading older
  content, and the existing jump-to-latest affordance remains available.
- Sidebar children use a continuous manager rail with a short branch into each row. One-shot descendants move that
  same tree visual inward rather than adding another decorative arrow.
- The spawned-agent panel labels nested work as **under _parent worker_** and uses the same rail treatment, making
  ownership clear even when parent and child runs are separated by newer activity.
- Conversation and composer maximum width increases from 900 px to 960 px for slightly better use of manager and
  worker panes without turning messages into difficult full-window lines.

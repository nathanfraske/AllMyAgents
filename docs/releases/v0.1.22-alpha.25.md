# AllMyAgents v0.1.22-alpha.25

Released 2026-08-08.

## Purpose

This release closes the remote-fleet reliability arc and the restart/deletion regressions found while exercising
the prior cut against the operator's live journal. It keeps a healthy direct mesh conversation online through
transient discovery failures, gives every remote mutation an idempotent durable identity, transfers directory
trees instead of only individual files, restores interrupted Claude work after a hub restart, and prevents large
project deletion preflights from blocking the app.

It also corrects the lifecycle model for retired manager children. Retirement remains the reversible escape hatch
that preserves evidence and frees a bounded live slot, but retired chats are records—not working roster members—
and no longer accumulate in the sidebar or Overseer catalog.

The preceding cut's complete feature log remains in
[`v0.1.21-alpha.24.md`](v0.1.21-alpha.24.md); this document records every operator-facing change since that tag.

## Remote fleet stability and one-way trust

- A currently open direct mesh WebSocket is authoritative evidence that the peer is reachable. A transient Site
  health request or fleet refresh can mark only genuinely disconnected peers offline; it cannot overwrite the
  open stream's sessions, projects, profiles, or reachability state.
- Passive `/api/fleet` polling no longer invokes route recovery. Route creation/recovery occurs only on explicit
  refresh, preventing a slow health probe from repeatedly tearing down and recreating a working bridge.
- Saving an unchanged direct connection is idempotent. The hub reports whether the connection actually changed
  and journals `fleet/connection-paired` only for a real token/label transition, reducing route churn and journal
  amplification.
- One signed-fleet trust operation establishes the reciprocal connection. A second code from the opposite machine
  is not required. Directly reachable peers still expose optional code entry as a compatibility and recovery path
  when automatic signed-fleet trust is unavailable.
- Remote profile/account pickers render a compact, human label rather than the full mesh-qualified internal key.
  The qualified identity remains underneath for correct routing and never leaks into the normal selector label.
- The dedicated Overseer is selected only from this hub's local records. A paired peer Overseer remains a remote
  conversation and cannot usurp the local application-control entry.

## Exactly-once remote conversations

- Operator sends and mid-turn steers receive a stable client request id before leaving the renderer. The same id
  survives retries and direct/Site-compatible transport fallback, allowing the destination hub to return the
  canonical journal result rather than executing the mutation twice.
- Remote input, steer, and attachment events use canonical durable keys. A retried steer can no longer appear above
  earlier messages or create two user entries with only one provider turn.
- The renderer reconciles the acknowledged canonical event with its optimistic draft while preserving text typed
  after the send began. Attachments remain part of the durable chat item across reload instead of disappearing as
  transient composer state.

## Remote folders, WSL, and diagnostics

- The remote-device protocol adds bounded directory creation and recursive folder transfer. Relative paths are
  normalized and contained beneath the operator-granted root; traversal, symlink escape, over-depth trees, and
  quota violations fail closed.
- Directory trees can target native roots or a granted WSL distribution. Destination creation and file writes use
  the same exact remote capability boundary as individual file operations.
- Transfer results expose bytes, elapsed time, throughput, peer latency, and the exact failed relative path. A
  partial or rejected transfer is never presented as complete.
- The remote testbed documentation now records the fleet trust, environment discovery, WSL, transfer-progress,
  and GitHub runner directions, while broader hardware-hub and runner ideas are retained in
  [`hardware-hub-and-fleet-ideas.md`](../hardware-hub-and-fleet-ideas.md).

## Restart continuity for Claude

- The Claude adapter surfaces its vendor session id as soon as the provider establishes it rather than waiting for
  final turn completion. The hub persists that identity through both in-process and worker-owned execution paths.
- When the hub restarts after accepting a turn, the next provider request receives a bounded continuity capsule
  built from durable journal semantics: the active objective, recent user/assistant conversation, interruption
  marker, and exact unanswered interactive question when one exists.
- Commands, tool output, and raw provider protocol envelopes stay out of the capsule. The capsule is a continuation
  aid, not an invented completion, and it does not overwrite the provider's own resumed thread memory.
- Regression coverage exercises both normal early identity persistence and a restart before the turn's final
  lifecycle event, so “ask me those again” can recover from the transcript instead of starting as a blank chat.

## Project deletion without renderer freezes

- Project work inspection runs asynchronously with a server-side deadline and a shorter UI abort boundary. Git or
  filesystem inspection of a large/stale checkout can no longer hold the desktop renderer in “Inspecting local
  work before deletion…” indefinitely.
- Preflight output is bounded by file/commit/worktree counts and reports truncation honestly. The confirmation still
  names the exact project root and separates safe catalog removal from destructive file/chat deletion.
- Removal performs bounded asynchronous workspace cleanup and returns an exact timeout or failure. The dialog stays
  cancellable and usable after a failed fetch rather than wedging the entire app.

## Journal write and maintenance pressure

- A condensation pass with no eligible frontier no longer hashes and integrity-checks a full recovery generation.
  It records a truthful zero-work completion after the replication prune gate, avoiding gigabytes of read/copy
  work for a no-op maintenance interval.
- Codex command-output deltas from the worker channel are losslessly coalesced for a 16 ms / 64 KiB window. The hub
  flushes before lifecycle, non-delta, stale-reset, or deletion boundaries, preserving exact visible output and the
  highest durable worker sequence while sharply reducing event-row overhead for verbose commands.
- Maintenance remains progress-aware and size-budgeted from the previous cut; this release removes an additional
  no-progress amplification path rather than weakening integrity or lineage verification when rows are eligible.

## Retired agents are records, not roster entries

- `manage_child retire` remains reversible and does not append `session/deleted`. It preserves the session id,
  provider transcript, task history, worktree, dirty state, commits, manager/team attribution, retirement time, and
  reason while releasing one live-child capacity slot.
- Retired children are excluded from the sidebar working catalog and from `list_agents`, including the Overseer's
  otherwise fleet-wide catalog. They therefore cannot accumulate as apparently actionable stopped agents.
- Project Overview includes a collapsed Retired agent records section. It provides the immutable short id, reason,
  timestamp, and a route to open the preserved transcript without mixing the record into live status counts.
- Manager `child_status` and per-turn topology distinguish the active catalog from retired records and retain exact
  ids needed for `manage_child reactivate`. Team summaries count active agents and archived records separately.
- Provider-native manager instructions now say that an idle worker is reusable. Managers prefer a real compaction
  boundary for unrelated work and retire only when replacement is genuinely required or context recovery is
  unavailable, preventing routine task completion from manufacturing archives.

## Known boundaries

- The exact release tag remains the authority for cross-platform CI and signed updater artifacts. This Windows
  workstation does not hold the protected updater private key, so its local installer build can validate payload
  and unsigned artifacts but cannot publish a signed updater bundle.
- macOS installed-launch behavior and the updater round-trip retain the documented alpha limitations in
  [`alpha-cut-checklist.md`](../alpha-cut-checklist.md).

## Updating

Existing installs can use **Settings → Check for updates** after the signed release assets are published. The
GitHub release also provides Windows MSI/NSIS and Apple Silicon/Intel macOS downloads. Windows SmartScreen and
macOS notarization warnings may still appear during the alpha; updater signatures and release checksums remain the
integrity boundary for this cut.

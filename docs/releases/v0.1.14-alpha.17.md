# AllMyAgents v0.1.14-alpha.17

Released 2026-08-03.

## Purpose

This patch fixes a live chat that could remain visibly frozen at an old assistant message even while new
operator input reached the agent and the hub continued journaling every reply. It is a renderer catch-up
and bounded-history repair; no missing journal data had to be fabricated or recovered.

## Confirmed failure

- The affected native Codex session remained `active`, accepted new operator input, and continued producing
  normal provider events.
- The hub health probe reported a complete boot with active journal-backup ownership.
- An independent authenticated WebSocket connection returned an ordered replay-start, every requested tail
  event, and replay-complete boundary.
- The missing assistant messages were present as durable `codex/item/completed` rows in the live journal.
- The visible renderer remained at its 8:08 PM cutoff because its prior cursor had stopped advancing.
- A 60-page read retrieved 3,908 raw session rows covering only 53 minutes. Token deltas, reasoning deltas,
  command output, status, and usage rows crowded completed messages out of each 80-row history page.

## Renderer overflow repair

- Live events still batch to avoid rendering and scrolling once per WebSocket frame.
- When a paused renderer accumulates 1,024 pending live events, the 1,025th event now synchronously drains
  that finite batch and remains queued for the normal frame flush.
- The old behavior requested a cold baseline at that boundary. That discarded the pending transcript facts
  and advanced the durable cursor beyond the very messages the operator had not rendered.
- FIFO order, duplicate sequence protection, per-event exception isolation, replay presentation marking,
  and the 2 MiB client memory bound remain intact.
- A single incompatible frame larger than the protocol limit still fails closed into a truthful baseline
  reset. Current hubs cap a frame at 512 KiB, so ordinary live delivery never takes that path.
- The staged replay allowance now comfortably contains the server's bounded tail plus replay-start and
  replay-complete controls instead of rejecting the boundary controls themselves near the old limit.

## Baseline recovery repair

- Installing a required current-state baseline intentionally replaces native session views and clears their
  historical-window state.
- The store now captures the still-open layout and immediately requests the latest bounded journal window
  for every selected and split-pane session after that replacement.
- This is necessary because the session id does not change across a reset, so `ThreadView` does not remount
  and `select()` cannot be relied on to trigger history hydration.
- History hydration is fire-and-forget relative to reconnection. A slow history read cannot delay the new
  WebSocket, and live items arriving first are merged with the recovered window by stable item keys.

## Semantic journal history

- The history endpoint now applies its row and byte bounds to transcript-semantic rows rather than all raw
  worker-protocol rows.
- Retained semantics include operator input, bus traffic, recovery questions, errors, permission/worktree
  notes, recalled-memory boundaries, complete Claude messages/results, complete Codex items/turns, and
  context-compaction lifecycle events.
- Codex terminal item rows contain the complete assistant, reasoning, tool, or file-change payload. Their
  preceding text/output deltas are redundant for historical reconstruction and no longer consume page rows.
- In-progress Codex context-compaction starts remain visible through a bounded JSON-validity-checked clause.
- Filtering affects only the read-only renderer projection. The source journal, worker cursor, replay stream,
  backup, recovery, and condensation rules are unchanged and remain lossless.
- Generation compare-and-swap, session-index completion checks, individual oversized-event markers,
  the 80 semantic-row maximum, and the 512 KiB encoded-page maximum remain enforced.

## Regression coverage

- Added a renderer regression that pauses scheduled flushing across 1,025 events and proves no baseline
  refresh occurs, sequences 1 through 1,025 advance in order, and the queue drains to zero.
- Added a baseline-reset regression with a selected native chat. It proves the stale view is replaced and
  the recovered completed assistant reply is loaded automatically without a selection change.
- Added a real SQLite regression with 600 redundant Codex delta rows around a completed response. A five-row
  semantic page returns the operator input and complete reply immediately and reports no false older page.
- Ran the production semantic query read-only against the operator's 1.45 GB live journal: it returned 81
  semantic rows in 16.41 ms, including the currently missing completed replies.

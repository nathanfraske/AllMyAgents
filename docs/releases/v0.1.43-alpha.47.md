# AllMyAgents v0.1.43-alpha.47

## Less repeated context for managers and agents

Run starts, cancellation acknowledgements, inspections and team queries now share a
compact run summary. Exact records remain available with `detail: "full"`; retained
logs, cursors, prerequisite IDs, admitted timeouts, provenance, failure diagnostics
and unknown-outcome protections are preserved. Quiet inspections reinforce using
completion notifications rather than repeatedly polling unchanged output.

Agent rosters group under project headings and child rosters under active/stashed
teams, rather than repeating the same IDs on every row. Full agent IDs remain intact.
Codex and Claude tool discovery omits the large Overseer control declaration for
ordinary agents and managers. Discovery uses the bound hub identity; all execution
authorization remains unchanged. Existing sessions see this on their next provider
tool-discovery refresh.

The TOON investigation found larger savings from these changes than from replacing
JSON. This release keeps compact JSON and adds no TOON runtime dependency. Response
size measurements are not claims about total provider billing savings. See the
[measured evaluation](../mcp-toon-evaluation-2026-09-09.md).

## Usage resets and coordination

- Exhausted or near-exhausted Codex accounts refresh more promptly. A blocked dispatch
  refreshes the observation with a single-flight bound, and an expired quota window
  no longer blocks new work using its old 100% value.
- Explicitly addressed messages between local project agents/managers and the
  application Overseer cross project boundaries. Other cross-project routing remains
  scoped; message delivery does not confer operator mutation authority.

## Journal and history stability

- Payload validation uses resumable bounded batches instead of scanning every event
  every maintenance cycle. Unchanged cycles validate no payload rows. This does not
  remove independent snapshot verification or weaken deletion coverage requirements.
- A snapshot postponed by maintenance retries promptly rather than being treated as
  a successful backup and waiting another large-database interval.
- Maintenance that is current through its verified recovery snapshot is shown as an
  ordinary wait, not an unavailable journal. Real missing coverage and failures remain
  visible warnings/errors.
- Baseline refresh preserves loaded transcripts until replacement history succeeds.
  Failed loads retain the visible history and retry error; superseded failures cannot
  overwrite a newer request's loading state. Live and restored history stay ordered.

These repairs address reproduced maintenance and history-refresh defects. They do
not claim every intermittent live disconnect or eight-second timeout has been
eliminated. Details and multi-GB test results are in the
[journal/usage investigation](../manager-usage-and-journal-status-2026-09-09.md).

## Verification and updating

Regressions cover exact/full run views, remote unknown outcomes, cursor paging,
mixed rosters, provider discovery parity, role/binding checks, quota resets,
cross-project messaging and journal/history refresh races. Publication is gated on
cross-platform JS/native checks, credential/payload audits and exact-tag Windows/macOS
launch-and-repair verification.

The numeric application version increases to **0.1.43**. After publication, use
**Settings → Check for updates**. The signed updater carries the new version.
Publishing does not restart an app, service or operating system; installation is
still an operator action. No OS reboot is required.

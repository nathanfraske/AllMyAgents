# AllMyAgents v0.1.12-alpha.15

Released 2026-08-02.

## Highlights

- Added operator-approved remote device testbeds over paired AllMyStuff fleet connections, including
  bounded file and terminal access on Windows, macOS, Linux, and explicitly granted WSL distributions.
- Added a projectless application Overseer with operator-level, hub-audited controls and supervisor
  diagnostics that remain readable when the journal or account cache cannot boot.
- Added managed-workspace pressure warnings and conservative orphan-worktree reclamation, and fixed SQLite
  backup sidecars that were left behind during rotation and partial cleanup.
- Made Claude and Codex context compaction a first-class full-width chat lifecycle rather than hidden step
  noise, including replay and lazy-history reconstruction.
- Fixed composer races, post-login UI stalls, false recurring OAuth sign-outs, and misleading cold-start
  connection status.

## Remote machines and unified fleet

- Paired AllMyStuff hubs now appear in one fleet view with namespaced projects, accounts, sessions,
  approvals, questions, usage, live WebSockets, bounded replay cursors, and lazy transcript history.
- Remote projects choose accounts from their owning machine. Manager templates, usage-aware roles, detached
  chat defaults, imports, and account switching no longer leak a local profile id into a remote launch.
- A remote target is disabled by default. The operator must expose exact roots and exact capabilities on the
  target, then grant an individual source chat the target/root/capability tuple.
- Agents receive provider-neutral remote list, read, write, and terminal tools with bounded request data,
  command time, output, and response sizes. Revocation and target-policy narrowing take effect immediately.
- Windows targets can expose an individual WSL distribution and Linux root independently of the Windows
  filesystem. Containment uses canonical Linux paths and includes the distribution in the grant identity.
- Environment discovery reports platform, shell, available WSL distributions, root accessibility, and
  capability limits. Ping and file operations report route, network, target, and round-trip time, byte
  counts, throughput, and actionable pairing/route/transport/timeout/protocol/target failure stages.
- Remote device tokens are retained in a hub-private write-only connection store; server-side relays use the
  credential without returning it to the renderer or model.

See [remote device testbed operation and security](../remote-device-testbeds.md) and the updated
[mesh fleet design](../mesh-unified-fleet.md).

## Application Overseer

- Settings can designate one managed Claude or Codex account for a durable projectless Overseer chat rooted
  at the application checkout.
- During a direct operator-originated turn, the Overseer can inspect system state; create projects and
  chats; send, stop, and reopen chats; apply explicit permission overrides; decide pending approvals; and
  request a supervised hub restart.
- Overseer authority is hub-minted and identity/provenance checked on every control call. Manager, teammate,
  file, tool-output, and web content cannot manufacture an operator turn or inherit this role.
- The supervisor writes a small token-free status breadcrumb outside SQLite for startup, recovery, retry,
  restart, and offline states. The native desktop can read it when the hub API and journal are unavailable.
- The boundary is explicit: supervisor diagnostics survive journal failure, while vendor reasoning and
  state-changing Overseer actions resume only after the authenticated hub is healthy.

See [the Overseer trust and recovery model](../application-overseer.md).

## Workspace and backup containment

- The hub measures managed checkouts with bounded, non-symlink-following scans. It warns at 4 GiB total,
  2 GiB of recognized dependency/build output, or low free disk, and escalates at 12 GiB, 8 GiB, or
  critically low disk. Hysteresis and a 24-hour reminder cadence prevent notification churn.
- A running agent receives pressure feedback at the next tool boundary; later turns receive the same fact
  through managed instructions. The chat and sidebar show measured totals, artifact groups, free space, and
  whether a bounded scan is a lower limit.
- Startup now reaps a worktree with no owning session only when Git proves it contains no uncommitted work
  and no commit unreachable from another non-agent ref. Regenerable `node_modules`, `target`, `dist`, and
  `build` output and an untouched hub-authored instruction block do not pin an otherwise empty orphan.
- Git errors, corrupt/non-checkout directories, authored instruction content, dirty files, and unmerged
  commits all fail closed and keep the worktree. Active work and build output are never auto-deleted.
- Backup rotation now deletes each retired database's `-wal` and `-shm` files. Stale partial cleanup also
  recognizes `.db.partial-wal` and `.db.partial-shm`, closing the per-generation sidecar leak on Windows.

See [managed workspace size safeguards](../managed-workspace-size-guards.md).

## Chat, history, and compaction

- Sending a new turn or steering an active turn now transfers the submitted payload out of the composer
  immediately. A late success can no longer erase text typed while the request was pending.
- A failed dispatch restores the submitted text, paste chips, and attachment chips ahead of anything typed
  afterward. Successful attachment uploads are retained for retry rather than uploaded twice.
- The same transactional behavior covers first-message draft materialization: text or files staged during a
  delayed draft-to-real id transition follow the real chat instead of being reset.
- Startup-phase Enter continues to queue rather than racing an unavailable steer stream.
- Claude and Codex compaction now render started, completed, failed, and explicitly unobservable terminal
  states as full-width timeline entries. Live and historical reducers correlate duplicate/boundary events
  without inventing a successful completion.
- Remote and local long history use bounded baselines, per-site cursors, lazy pages, and reconnect-aware
  refresh rather than an unbounded initial replay.

## Accounts and login

- A durable successful login transitions the account UI to complete before the best-effort profile rescan.
  A slow or wedged presentation refresh no longer leaves the blocking modal displaying `waiting…` after the
  credential and login registry already succeeded.
- The recurring logout cause was access-token classification: profile rescans treated an expired short-lived
  access token as a permanent sign-out even when a refresh token was present. Such credentials are now
  honestly `unknown/refreshable` and may run so the vendor can refresh them lazily.
- Missing/malformed credentials and expired access tokens without refresh material remain signed out. A real
  vendor refresh failure such as `invalid_grant` remains authoritative and is not erased by a later rescan.
- Internal `claude-default` and `codex-default` vendor-home bindings remain available for import/resume but
  are filtered from local replay, rescans, and remote fleet account pickers.

## Startup and control-channel security

- Cold launch now shows `Starting hub…` with elapsed time and supervisor diagnostics. `Reconnecting…` is
  reserved for a socket that was previously connected and then lost, so startup no longer looks like an
  unexplained outage.
- The long-lived local hub/worker channel now uses a mutually verified HMAC handshake with fresh nonces and
  replay checks. A same-user process cannot replace the hub, forge apply/run/ACK traffic, or pin a forged
  higher epoch merely by connecting to the deterministic local endpoint.
- The channel secret is process-lifetime only and is removed from child environments that do not need it.

## Safety and compatibility

- Remote execution is deny-by-default at both the target and source-chat boundaries.
- Workspace cleanup never removes a checkout unless Git proves it contains no unique work.
- OAuth refreshability is not presented as proven sign-in; it merely stops local expiry from making the
  stronger and often false claim that the account is permanently signed out.
- Existing journals, projects, sessions, account ids, grants, and vendor credentials remain compatible.
- The updater version advances from 0.1.11 to 0.1.12 so installed clients can discover this cut.
- This remains alpha software. Windows installers are not Authenticode-signed, and macOS bundles are not
  notarized.

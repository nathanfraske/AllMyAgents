# AllMyAgents v0.1.28-alpha.32

Released 2026-08-15.

## Purpose

This release repairs four control-plane boundaries that were still costing operator time after alpha.31: cold
history hydration blocked the hub and then looked like an empty chat, remote durable runs recorded a long timeout
but were killed at two minutes, operator input arriving during a teammate turn lost its authority, and operator-
granted GitHub automation did not reach Codex connector elicitations.

It also gives already-deployed Linux testbeds a bounded update path, surfaces real startup progress in the desktop,
removes legacy backup sidecar wreckage through ordinary retention, and makes the Overseer's standing approval
authority usable without widening teammate-caused turns generally.

## Cold history without a frozen hub

- A history request first plans which rows can fit inside the bounded 512 KiB page from inline JSON and immutable
  blob metadata. It no longer hydrates every candidate only to discard most of it afterward.
- Selected blobs use asynchronous filesystem reads with a store-wide 16-read semaphore. Identical in-flight digest
  reads coalesce, so several panes cannot multiply the same disk work.
- The working-set cache grows from 16 MiB to a bounded 128 MiB. Unrelated active chats are much less likely to evict
  every blob belonging to an idle conversation.
- SQLite snapshots close before blob I/O, avoiding a slow disk read holding a WAL generation open.
- Oversized or unreadable retained events remain explicit evidence. The implementation does not truncate or invent
  transcript content to fit a page.
- The client distinguishes loaded-and-empty, loading, retryable indexing/generation changes, timeout, and failed
  history. A failed request now renders the error and a Retry history action instead of "no activity yet".
- Bounded retry uses fresh abort signals; a timed-out request cannot continue consuming the request slot unseen.

## Durable remote work that honors its record

- `start_run` accepts and uses one timeout end to end, from one second through six hours. Interactive `remote_exec`
  keeps its separate two-minute ceiling.
- The lightweight executor receives the durable run id and therefore uses the durable timeout instead of silently
  clamping it to 120 seconds.
- Timeout failures are classified as timeout evidence rather than an ordinary target command failure, and the run
  record cannot claim a budget the target did not use.
- Remote provenance records the target OS, architecture, root/cwd, transport, environment, and available toolchain.
  A RISC-V result no longer presents itself as a Windows/x64 build merely because the coordinating hub ran there.
- The run controller retains exact terminal state, bounded cursor-paged logs, cancellation, resource leases, and
  `outcome_unknown` behavior for ambiguous transport boundaries.

## Operator authority across a live teammate turn

- An authenticated operator message that arrives while a bus-origin turn is active never relabels that running
  turn. Existing teammate work stays permission-clamped exactly as before.
- The exact text, attachments, and model/effort overrides are durably queued as a fresh operator-origin turn and
  start automatically at the next genuine idle boundary. The operator no longer has to notice and retype it.
- A best-effort steer lets the current turn see guidance immediately, but it is explicitly told that operator-only
  mutations must wait for the new boundary.
- Dispatch changes to `dispatching` before crossing the provider boundary. A restart with an ambiguous prior
  dispatch reports `outcome_unknown` and never replays a mutation that may already have completed.
- Pending teammate mail is not bundled into the fresh privileged turn. Semi-trusted text cannot inherit the new
  operator authority.
- Regression coverage proves the old turn is denied, the fresh turn succeeds, the input is journaled once, and the
  authorized mutation runs exactly once.

## GitHub connector automation and approval history

- The existing operator-owned GitHub policy now recognizes the exact Codex `codex_apps` GitHub connector approval
  envelope. It requires the GitHub connector, an empty approval form, one explicit repository, and a closed
  operation grammar.
- `pull_requests`, `pull_request_merges`, `workflow_runs`, and `repository_pushes` remain separate capabilities. A
  pull-request grant cannot merge, push, run workflows, administer a repository, or approve an unknown tool.
- Project-attached sessions remain confined to the project's live Git remote. Ambiguous or missing repositories,
  mismatched scopes, explicit ask rules, local command shadows, force pushes, and active hooks fail closed.
- Auto-satisfaction is fully audited with operation, scope, repository, scalar identifiers, and SHA-256/length
  summaries for free text. Large PR bodies are not duplicated into another unbounded journal payload.
- Approval dispositions have a small durable SQLite ledger with status, timestamps, decider, and optional connector
  persistence. `query_team` and Overseer status retain recent decisions after they leave the pending inbox and after
  a hub restart.
- Overseer `approve` defaults to one-shot. `persist=session` or `persist=always` is accepted only on a direct
  operator turn, only for approval, and only when that exact Codex request advertised the selected scope.
- A configured standing Overseer policy may decide only the exact hub-minted alert, never its own request, and only
  within its low/medium semantic ceiling. Connector body/comment updates normalize to the same medium-risk class;
  merges, pushes, workflows, close/reopen, and unknown operations remain operator-bound.

## Lightweight testbed lifecycle

- `sync_testbed_node` reconciles an already-paired Linux systemd testbed to the release without reinstalling vendor
  accounts or the full UI. It compares per-file SHA-256 values and transfers only changed JavaScript modules plus
  build identity metadata.
- Each staged file is size bounded and re-verified on the target. Application uses temporary files, atomic rename,
  rollback capture, and a service-layout proof derived from the installed systemd unit.
- Restart is scheduled through a detached transient unit after the request can reply. A severed response is treated
  as ambiguous and resolved only by read-only build-identity polling; the mutation is never blindly retried.
- Status reports explicit `myownmesh-rpc` or `site` transport and checksum-backed payload/code ids, app version,
  source commit, and public SSH host-key fingerprints.
- Linux execution uses a non-login shell and, for elevated testbed profiles, an isolated transient systemd unit so
  child output does not bury the node's own journal. Service units order after `myownmesh.service` and persist the
  detected control-socket path explicitly.
- The portable README now matches the security boundary: MyOwnMesh is the required transport, AllMyStuff is optional
  bootstrap convenience, automatic fleet trust is off by default, and one-use pairing is the ordinary path.
- The synchronizer is covered by rollback, changed-file, already-current, ambiguous-restart, identity, transport,
  and cross-architecture tests. The current RISC-V node was manually reconciled to matching module hashes before
  this release; the new automatic synchronizer still requires an explicit operator invocation for its first live
  hardware exercise.

## Startup, retention, and Overseer polish

- Ordinary startup keeps `quick_check` on the readiness path and moves the exhaustive per-event JSON scan into the
  isolated post-ready maintenance child. Stable-family recovery still performs the exhaustive proof before restore.
- The desktop reads only a bounded 64 KiB tail of the current boot log and renders the live preflight/restoration
  phase with elapsed time. Native process start to first painted renderer frame is now measured separately.
- Backup rotation removes ordinary-file `-wal` and `-shm` sidecars whose main snapshot no longer exists, never
  follows symlinks, and repeats idempotently on normal retention cycles.
- Stale worktree records stop spawning failed Git probes until the checkout reappears, and profile ownership no
  longer reports a normal restart reclaim as a new incident.
- Existing Overseers upgrade in place to capability contract v21. The generated methodology names the correct
  operator-vs-bus messaging path, evidence/retraction discipline, project delegation, durable-run/testbed workflow,
  GitHub grants, persistence boundary, task accountability, and compaction continuity.

## Updating

Use **Settings → Check for updates** after exact-tag verification and signed assets finish publishing. The release
page will provide Windows MSI/NSIS installers and Apple Silicon/Intel macOS downloads.

For macOS, the supported alpha install command remains:

```sh
curl -fsSL https://raw.githubusercontent.com/nathanfraske/AllMyAgents/main/scripts/install-macos.sh | bash
```

Windows SmartScreen and macOS notarization warnings retain the documented alpha behavior.

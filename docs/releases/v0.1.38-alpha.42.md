# AllMyAgents v0.1.38-alpha.42

Released 2026-08-31.

## Purpose

This release fixes an exact-once defect in operator input delivered to a manager while a teammate-origin turn is
already active. The transcript showed one operator message, but the model could receive that text twice: first as
permission-clamped live guidance and later as the fresh operator-authorized turn.

## Operator input exact-once delivery

- Operator text arriving during a non-operator turn is durably queued but no longer steered into that live turn.
- The running teammate turn keeps its original permission boundary and never gains operator authority mid-flight.
- When the turn becomes idle, the hub starts one fresh operator-origin turn with the original text and attachments.
- Rapid follow-up corrections queued behind the same turn are coalesced into one bounded chronological operator
  batch. Every message remains intact and visible once, while later entries supersede earlier ones only where they
  explicitly conflict. This avoids a manager spending a series of long turns on obsolete intermediate directions.
- The transcript retains one `session/input` event; the deferred record now declares `fresh-turn-only` delivery so
  the decision is explicit in the audit trail.
- Existing restart safety remains intact: a dispatch crossing an ambiguous hub handoff is reported as
  `outcome_unknown` and is never blindly submitted a second time.

## Current instructions cannot regress to stale saved prose

- The live MoM manager also had saved task and standing prose from August 20 which still named PR #5 and required
  an audit/hold loop, despite much newer direct operator directions. This protected text could pull the manager
  back toward an obsolete workflow after a later turn, restart, or compaction.
- Manager protected instructions now state the exact precedence without copying more conversation into context:
  saved manager prose is background, while newer authenticated direct operator input controls wherever it
  explicitly conflicts on target, hold, sequencing, or workflow.
- The generated block includes the observed configuration and latest-direct-input timestamps. It does not include
  message bodies, so the fix does not create an unbounded prompt-growth or length-poisoning path.
- Managers are told to ask if the current goal is genuinely ambiguous, never resurrect an old assignment merely
  because durable prose was re-rendered.

## Live evidence

The operator's MyOwnMesh V4 Transition manager showed the defect directly in the journal. Messages sent during bus
turns had both a `session/steered` event and a later `session/turn-origin` event tied to the same deferred input,
sometimes many minutes apart. That explains replies which appeared to target old operator instructions. The new
path has one model-delivery boundary instead of those two.

## Verification

- The focused mid-turn suite covers single and multi-message exact-once dispatch.
- The regression asserts that the active bus turn receives no operator steer, the queued fresh turn receives the
  original text exactly once, rapid corrections arrive once in chronological order, the transcript records one
  input per operator message, and the authorized mutation occurs once.
- Manager-roster coverage pins the saved-prose precedence rule in both native and protected runtime instructions.
- Hub typecheck passes.
- The exact-tag release workflow re-runs the full credential firewall, installed launch-and-repair gates, platform
